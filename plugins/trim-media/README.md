# 飞牛影视（`trim-media`）

把飞牛影视（fnOS 影视）变成 MovieClaw 的**播放器伙伴**，而不是另一个孤岛：库是 MovieClaw
自己的库，进度两边同步，片头片尾一次识别两边都生效。

## 三个能力

### 1. 库接入：飞牛的库，MovieClaw 的库

同步任务发现飞牛上的媒体库，把「本机看得到目录」的库建成本地媒体库
（`library.create`）。建出来的是**普通本地库**：

- 目录写的是飞牛库目录在本机的挂载路径，识别 / 刮削 / 海报墙 / 详情 / 播放 /
  Jellyfin 全是 MovieClaw 主线原生行为；
- **飞牛挂了照常播**——库和文件都在本地，飞牛只是另一个管理端；
- 元数据不重复刮削：主线自己的识别刮削链跑一遍就够，飞牛的音视频文件原封不动。

需要两项配置：**飞牛路径前缀**（飞牛里那批文件的路径开头，如 `/mnt/media/Movies`）与
**本机路径前缀**（容器里对应的路径，如 `/downloads`）。两个都填才接入，只填一个
等于没配。换算不出本机路径的库不接，在「接入预览」里说明原因。

认领关系记在插件自己的数据里（`ledger`），不依赖主线的库行。**只加不删**：飞牛上
删了库，本地库与文件不动——兜底库的意义就在这里。

### 2. 观看进度双向同步

- **MovieClaw → 飞牛**：订阅播放事件，近实时把位置写给飞牛。进度事件每集最多 30 秒
  一条，插件再加 20 秒节流；停止 / 看完**不节流**，这两个时刻必须准。
- **飞牛 → MovieClaw**：定时（默认 60 秒）拉飞牛的「继续观看」，写回 `playback.sync.state`
  （带 compare-and-set 与事件抑制，不自己动观看状态）。MovieClaw 这边刚有播放动作时
  自动加速到 5 秒一轮，静默后回到常态。

两侧**共同有的片**才同步，靠 (TMDB, 季, 集) 收敛，和文件放在哪无关。已在 MovieClaw
看完、飞牛还没看完的，不会被拉回未看完。

一个飞牛账号对应一个 MovieClaw 成员（设置里填成员用户名，留空表示超管）：飞牛的进度
按账号存，把全家人的进度都写进同一个账号会让家人看过的东西显示为已看。

### 3. 片头片尾写回

MovieClaw 识别完一季的片头片尾（`library.segments.updated`），插件按季取中位数写进
飞牛（`skip_opening` / `skip_ending` 秒）。飞牛按季存、整季生效——之后在飞牛里播也会
自动跳过，不用在两边各识别一遍。

值没变就不调接口（事件可能重复投递）；没有结论时不写，避免把飞牛已有配置覆盖成 0。

## 安装与配置

1. 安装插件，在「设置 → 插件 → 飞牛影视」填飞牛地址、用户名、密码（开了设备访问码才填）；
2. 如果飞牛库目录在本机可见，填上路径映射的两个前缀；
3. 「接入预览」看飞牛上哪些库能接、哪些跳过（含原因）；
4. 等 6 小时一次的自动同步，或在管理页点「立即同步」。

三个开关可以单独关：自动接入新库、同步观看进度、同步片头片尾。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `library.list` / `library.create` / `library.scan.start` | 发现库、建库、触发扫描 |
| `library.items.segments` | 读 MovieClaw 识别出的片头片尾结论 |
| `playback.sync.catalog` / `playback.sync.state` | 查观看状态、写回进度（危险操作，写的是观看记录） |
| `members.list` | 把配置的成员名解析成成员 id |
| `playback.progress` / `stopped` / `completed` | 敏感事件：知道谁在什么时候看了什么 |
| `library.segments.updated` | 知道一季的片头片尾识别完了 |
| `network` | 访问飞牛影视服务 |

## 边界

- 不写 MovieClaw 的数据库台账，一切经宿主操作；写入统一走 `playback.sync.state`，
  不重复实现可见性与并发控制；
- 事件处理只读 payload 快照（`media.tmdb_id` 等），不回查宿主库；
- 不改动飞牛的文件，不删 MovieClaw 的库与文件。
