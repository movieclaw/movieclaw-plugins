# beta.3 共同观看来源验证（2026-10-27）

本轮在 dev／PR #1 开发候选，不改正式 main／市场 0.2.3，不部署、合并或发布，不写真实 Trakt。用户授权先完成可证明的插件修复，确认缺口后才提上游 PR；上游提案为 [MovieClaw #1063](https://github.com/movieclaw/MovieClaw/pull/1063)，提交 `fb8b05cd32ad2011affc329601af8a8f7956273b`。前一份 beta.2 验证报告保留为历史证据。

## 已复现的缺口

官方 v0.43.0 的完成事件没有目录所用的观看日志 ID。原生完成 12:34:59、Trakt 实际接收 12:35:01 时，远端保存 12:35:00；目录时间还可随 12:45 的停止更新。旧代码再次导出会额外写入源分钟，并错误报告完整成功。用相邻分钟或发生时间推断不能唯一关联两份记录。

## 配套修复

- 上游只在现有停止／完成事件增加可选 `watch_source_ids`，在现有目录 watches 中增加可选 `source_ids`，事件 minor 版本升为 1.1；旧字段和目录 canonical ID 保留。事件与目录调用相同续播分组，包含同次观看的全部日志 ID。在线／离线事件均提供来源，不新增端口、操作、权限或数据表。
- 插件在成员／绑定代次下持久保存共同来源回执，并核对媒体及单集身份。原生成功先保存回执再移除投递任务；导出同时写共同回执，晚到的实时事件也能复用。目录最终时间或续播 canonical ID 改变时仍可通过共同 ID 找到同次观看。
- 同来源实时任务待重试时，导出该行显示可恢复失败，不先行补写；实时恢复后再继续。分钟合并保持跳过结果，不伪称多次观看均被远端保存。升级前已发送但没有来源 ID 的记录无法自动恢复关联。
- 候选为 `0.3.0-beta.3`，清单要求停止／完成事件 `^1.1`。CI 固定提案提交；市场自动提交继续关闭，正式版本未变。
