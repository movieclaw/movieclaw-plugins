## 固定宿主与真实集成

- 官方 `movieclaw/MovieClaw` tag `v0.43.0`，commit `fae7ec10bf6aef8b12c819134930014fbe01d5cb`。直接下载官方源码并建立独立 Python 3.12 环境，不使用旧 API 提案分支。
- 隔离宿主采用真实 SQLite、数据库迁移、HTTP 网关、管理员／成员会话、可靠事件服务和插件入口。只有 Trakt HTTP 使用虚构凭据及模拟响应。
- 独立进程直接从本仓库 allowlist 打包产物解压启动，验证声明文件／运行代码／网页随包存在；组合宿主验收 8 项通过，包含新增电影及单集重看精确时间场景。
- 三次电影观看导入后保留原日期与时刻；不新增 PlaybackLog，不改变收藏、轨道和已有播放次数，清除符合条件的旧续播。重新识别、清理旧媒体锚点后，原事实与去重键仍存在，按修正后的编号导出。
- 同一单集 S01E02 的 `2021-02-03T04:05:06Z`、`2021-02-04T05:06:07Z` 两次观看分别落库，核对到秒；没有整季伪记录，没有触发手动操作回传循环。
- 用真实成员会话调用宿主已看、取消已看、收藏接口，经可靠事件写库投递至插件，分别访问 `/sync/history`、`/sync/history/remove`、`/sync/watchlist`，仅使用该成员的绑定。成员直接访问插件管理接口仍为 403。
- 生产服务器只做既有授权下的 catalog 只读查询，确认新字段与游标可用。没有向生产 import/state 或真实 Trakt 写入记录，没有读取或扩展用户凭据。

## 本轮修复与回归

- 普通写入 HTTP 400 作为单条失败；不会被误判为账号授权失效。
- 已结束但含失败项的手动任务不再占住调度顺序，后续操作可继续；显式暂停仍保持顺序。
- OAuth 400／Trakt 403 等真正授权失败将对应账号标记为需重连，阻止新事件堆积；其他成员继续正常发送。
- 已阻断的绑定无法通过历史导入或重试路径继续使用；宿主操作 403 只暂停任务，不使 Trakt 绑定失效。
- 保留正式版的元数据恢复、旧季集修正、按 ID 出队与容量保护、丢失提示确认、凭据隔离及公开应用配置。
- Confirm 前重新核查远端发生 403／429／503 时不抛未处理异常，不写入也不消耗预览；403 标记账号需重连，429／503 保留预览并遵守 Retry-After，等待期内重复点击不发远端请求。三个用例均先复现失败再修复通过。
- 当前提交 CR 的 P1：取消已看与独立播放队列顺序不一致。电影／单集、待发／失败四组用例均先复现“remove 后旧 history 又写回”，修复后旧任务及晚到旧事件被持久截止标记覆盖；另验证其他单集、成员、新绑定与之后的新观看不被抑制。
- 当前提交 CR 的 P2：预览后外部编号变化仍向旧编号导出。电影／单集两组用例先复现后修复，执行前编号不一致时跳过，连旧编号的远端查询也不发起。
- 复审 P2：旧手动已看失败后重试也必须遵守取消截止时间。新回归先复现 history → remove → history，再修复为旧任务跳过且不发远端查询／写入。另补测较新播放等待更早的待发取消，以及晚到旧取消不删除较新的已成功原生／手动观看；四项均先红后绿。
- 合并后的网页单条重试使用真实处理结果提示；手动操作的“忽略”取消对应任务，不再错调播放失败接口。移除“历史尚未接通”的过时提示。
