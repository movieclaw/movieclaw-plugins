# Technical and maintenance notes

History import verifies `user.ids.uuid` from `/users/settings` before scanning. A member-scoped encrypted UUID-to-source namespace survives disconnect/reconnect and username changes. Retained beta bindings adopt their original namespace only after UUID verification, persisting that mapping before updating the account so an interrupted migration cannot change existing record IDs. New bindings use the UUID namespace. Missing identity lookups retry or pause without host reads/writes; unfinished legacy import previews require cancellation and a fresh scan. See [Trakt's stable identity explanation](https://github.com/trakt/trakt-api/issues/182).

## Version 0.3

Version 0.3.0 targets official v0.44.0 and requires stopped/completed event contracts 1.1. Four host operations cover metadata reads, watch catalog and dated imports, with no filesystem permission. Manual actions and confirmed foreground history use separate durable plans; the playback-ledger limits below do not bound those plans. Terminal item errors do not block later actions. See the [workflow](sync-workflow.zh-CN.md).

Install and update through **Settings → Plugins → Plugin Market**, as described in the [README](../README.en.md). Users are not asked to switch server branches. The manifest requests playback events, network and plugin storage, without media deletion or media-file access.

Each member has encrypted credentials and a separate lock. Token rotation saves new tokens before reuse; a temporary save failure retains the new pair in memory rather than redeeming an old single-use token again. A 401 refreshes/replays once; OAuth refresh 400 or API 401/403 blocks that member and clears old pending tasks. Invalid write requests (400) are item failures rather than account authorization failures. Network failures retry with backoff. New events are skipped during blocked authorization until explicit disconnect/reconnect. No administrator-token fallback is allowed.

The ledger is bounded to 64 pending jobs/60 KB, 256 deduplication IDs, 16 sessions and up to 64 matching failures, subject to the total byte limit. Expired non-completion jobs and heartbeats are removed first, followed by other non-completions, and only then old completions. Discarded playback requests increase an unsynced-count warning that can be acknowledged without resetting cumulative totals or resending discarded items. Loss warnings do not permanently degrade connection health. Capacity and auth failures do not raise from the durable listener; actual persistence failures still propagate for host handling. Durable consumers are shared across members, so a permanently full per-member queue must not block the shared stream. This is bounded retention with explicit loss reporting, not unlimited delivery guarantees.

Activity is separately bounded to 80 entries/48 KB. Start/progress heartbeats are not logged or returned, including legacy heartbeat display entries. Credentials, request bodies, paths and device names are not exposed.

Migration enumerates plaintext ledger/linked scopes and reads credentials individually, so one corrupt encrypted account cannot block all members. Legacy non-administrator accounts without either marker are discovered on their next playback or a status lookup by member ID. Unexpected per-member failures back off for 10–300 seconds. Normal scheduling enumerates plaintext `delivery` markers and waits for pending work or the next retry deadline; it does not decrypt every account every five seconds. The account dashboard enumerates plaintext `linked` markers. Disconnect Trakt before deleting a MovieClaw member, because IDs can be reused and no member-deletion event is currently wired.

Completion is honored even with a cleared position. Delayed completion events retain the original `occurred_at`; this is not bulk history import. The optional `viewing_id` code path is retained as an extension, but official host payloads do not guarantee that field. Complete per-offline-viewing/rewatch history is not a supported claim. Nearby-history reconciliation reduces uncertain duplicate writes but cannot provide a distributed transaction or absolute exactly-once delivery.

The default public application is maintained by MovieClaw and uses secretless device authorization; see [APPLICATION.md](../APPLICATION.md). Do not bundle a Client Secret. Self-hosted custom applications can store their own secret encrypted by the host. Disconnect before changing client IDs. If they already differ, clear locally and report remote revocation unconfirmed rather than sending a new application's credentials to revoke an old grant.

For this repository, run its pinned host's `check_plugin.py`, then `python -m unittest discover -s plugins/trakt-sync/tests -t plugins/trakt-sync -v`, with `PYTHONPATH` set to that host's `src`. Use repository-root `scripts/generate_index.py --lint` and `scripts/pack.py plugins/trakt-sync --output dist/trakt-sync.mcplugin`. Runtime dependencies come from MovieClaw. Tests use fictional credentials and mocked Trakt; they are not real authorization acceptance. Published artifact hashes and signed catalogs come from this repository's release workflow.

## 0.2.2 recovery

Two read-only metadata operations (`library.list`, `library.items.get`) refresh external IDs and episode numbers by stable file ID. Failed jobs back off from 10 minutes to 6 hours; queued network backoff takes precedence to avoid busy loops. Completion replay checks paginated history at the source UTC minute before writing its minute-normalized timestamp. Trakt #694 discards remote seconds/microseconds; local chronology stays precise, and adjacent minutes remain distinct. Extra same-minute source watches cannot be exported separately; see the [precision contract](trakt-time-contract.zh-CN.md). Deleted local records retire the task; temporary missing/trash states wait. Legacy jobs without local IDs require manual season/episode correction or dismissal. No filesystem permission is requested.
