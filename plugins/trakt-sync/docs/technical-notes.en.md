# Technical and maintenance notes

Install and update through **Settings → Plugins → Plugin Market**, as described in the [README](../README.en.md). Users are not asked to switch server branches. The manifest requests playback events, network and plugin storage, without media deletion or media-file access.

Each member has encrypted credentials and a separate lock. Token rotation saves new tokens before reuse; a temporary save failure retains the new pair in memory rather than redeeming an old single-use token again. A 401 refreshes/replays once; failed authorization blocks that member and clears old pending tasks. New events are skipped until explicit disconnect/reconnect. No administrator-token fallback is allowed.

The ledger is bounded to 64 pending jobs/60 KB, 256 deduplication IDs, 16 sessions and 16 matching failures. Expired non-completion jobs and heartbeats are removed first, followed by other non-completions, and only then old completions. Discarded playback requests increase a persistent unsynced-count warning. Capacity and auth failures do not raise from the durable listener; actual persistence failures still propagate for host handling. Durable consumers are shared across members, so a permanently full per-member queue must not block the shared stream. This is bounded retention with explicit loss reporting, not unlimited delivery guarantees.

Activity is separately bounded to 80 entries/48 KB. Start/progress heartbeats are not logged or returned, including legacy heartbeat display entries. Credentials, request bodies, paths and device names are not exposed.

Legacy account enumeration/decryption happens once to migrate scheduler indexes. Normal scheduling enumerates plaintext `delivery` markers and waits for pending work or the next retry deadline; it does not decrypt every account every five seconds. The account dashboard enumerates plaintext `linked` markers. Disconnect Trakt before deleting a MovieClaw member, because IDs can be reused and no member-deletion event is currently wired.

Completion is honored even with a cleared position. Delayed completion events retain the original `occurred_at`; this is not bulk history import. The optional `viewing_id` code path is retained as an extension, but official host payloads do not guarantee that field. Complete per-offline-viewing/rewatch history is not a supported claim. Nearby-history reconciliation reduces uncertain duplicate writes but cannot provide a distributed transaction or absolute exactly-once delivery.

The official default application is intentionally unset pending organization ownership and real secretless refresh/revoke acceptance; see [APPLICATION.md](../APPLICATION.md). Do not bundle a Client Secret. Self-hosted custom applications can store their own secret encrypted by the host. Disconnect before changing client IDs. If they already differ, clear locally and report remote revocation unconfirmed rather than sending a new application's credentials to revoke an old grant.

For this repository, run its pinned host's `check_plugin.py`, then `python -m unittest discover -s plugins/trakt-sync/tests -t plugins/trakt-sync -v`, with `PYTHONPATH` set to that host's `src`. Use repository-root `scripts/generate_index.py --lint` and `scripts/pack.py plugins/trakt-sync --output dist/trakt-sync.mcplugin`. Runtime dependencies come from MovieClaw. Tests use fictional credentials and mocked Trakt; they are not real authorization acceptance. Published artifact hashes and signed catalogs come from this repository's release workflow.
