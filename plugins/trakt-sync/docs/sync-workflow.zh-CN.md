# 0.3.0：前台历史同步与共同观看 ID

0.3.0 需要正式 MovieClaw Server v0.44.0 或兼容后续版本。历史同步使用 #973 已发布的两个操作；实时投递和导出之间的共同观看 ID 使用[上游 #1063](https://github.com/movieclaw/MovieClaw/pull/1063) 的停止／完成事件 1.1 契约，已随 v0.44.0 正式发布。插件要求 ^1.1，会拒绝只有 1.0 事件的 v0.43.0。不使用用户 Cookie，不直连数据库。

## 用户功能

| 功能 | 实现与边界 |
| --- | --- |
| 手动标记已看同步 | 独立开关，默认关闭，只处理开启后事件 |
| 手动取消已看同步 | 独立开关，默认关闭；会移除对应电影／单集的全部 Trakt 观看记录，含重看 |
| 收藏同步 | 独立开关，默认关闭；新收藏加入 Trakt Watchlist，取消收藏不移除 |
| 评分 | MovieClaw 没有个人打分，因此不提供此功能或占位开关 |
| 活动筛选 | 观看、收藏、播放、全部，可与已发送／失败／待发送组合；默认隐藏播放噪声 |
| MovieClaw → Trakt 历史 | 网页手动扫描本地库；已看电影和单集按 UTC 分钟对齐；先预览再确认，本地源时间不变；同分钟额外观看不能分别保存，列为跳过 |
| Trakt → MovieClaw 历史 | 分页读电影和单集历史，匹配库内编号；保存 API 实际返回的观看时间和记录，标记已看；不能恢复远端已丢弃的秒数 |
| 同步历史 History | 额外页面只显示批次摘要，点击才分页加载电影／每季清单或每条记录结果 |
| 增量 | 持久回执跳过已成功记录；上次扫描没有排除截止时间之后的记录，且 Trakt 时间戳和本地库存都未变化时，不重新拉取历史 |
| 普通成员自助设置／额外设备配对 | Backlog，未接入。当前仍由管理员按成员管理独立 Trakt 绑定 |
| 关闭网页继续历史任务 | 不提供；实时事件的后台投递不受此限制 |

偏好存于插件的成员作用域 profile，不是把控件插入主程序的 profile 页面。管理员 ID 为 0，输入其他 ID 只选择目标成员数据与 Trakt 绑定，不切换 MovieClaw 登录身份。

## 网页流程

1. 点击一个方向的扫描按钮。创建任务本身不扫描、不写入；网页逐批调用 tick 才推进扫描。
2. 展示电影数、剧集数、季数、不同单集数和观看记录总数（含重看）。展开清单时，电影一行、电视剧每季一行；可另看每条观看日期、Trakt 分钟时间及处理结果。同分钟额外观看预先提示，结果列为跳过，不声称无损完成。不能勾选部分条目。
3. 等待 Confirm。确认不会启动后台任务；当前网页继续调用 tick 才写入，按批推进并显示进度。
4. 保持当前网页。切换标签页、暂停或关闭后不再发起下一批；正在执行的请求可能完成，已完成记录不回滚。浏览器离开提示不能硬性阻止关闭，也不能阻止系统终止浏览器。
5. 返回后手动打开任务并继续；不会自动恢复旧扫描或写入。取消停止剩余处理，不能撤销已完成记录。
6. History 显示批次截止时间和结果。只有本次匹配范围全部成功才显示全部完成；冲突／未匹配／失败不会被伪装为全库历史都已导入。

## 两边接口契约

上游提供通用 API，不包含 Trakt 代码、不新增监听端口或后台守护任务：

- `playback.sync.catalog`：管理员显式按成员、游标、页大小读取库内电影／单集、当前状态版本和已有观看事实。受管理员及目标成员库可见性、内容分级共同限制。
- `playback.sync.import`：管理员按成员、稳定源记录 ID、原观看时间、扫描时状态版本导入。读写权限分别申请；电影必须匹配外部编号，单集还必须存在于库内。导入不会制造 PlaybackLog、观看时长或播放完成事件；保留收藏、轨道和原播放次数（已看至少为 1）。导入的观看时间不早于本地最后播放时间时清除续播位置；较旧历史保留较新的本地续播，已有源记录重放不会清掉后来的续播。

重新识别或更正季集号时，导入的观看事实及源记录去重键会随文件迁移；批量换库保留媒体主键和这些记录。孤儿清理也会保留仅带导入记录的条目，避免级联丢失。

WatchRecord 新表保存外部历史事实，不等同于“在本机实际播放的会话”。上游现有播放时长统计不会因导入历史虚增。插件能从新 catalog 再读出这些重看事实。

原生观看使用上游现有完成判定与断点续播分组合并逻辑，不把原始 completed 字段误当每次重看的完成标志。仅有已看状态而没有完成观看事实时，使用存储的 last_played_at；旧资料没有该时间时回退 updated_at，并在预览中标识“采用本地状态时间”。这些数据不能还原未被保存的每一次手动点击，也不能声称其时间必然是点击时间。已有完成流水不会凭空再添一条手动观看。

## 大量记录、重试与增量

- 本地库存按游标分 50 个单元读取，Trakt 历史明确按 100 条分页，优先用分页头；没有分页头则读到空页。对重复分页暂停并保留检查点。
- 先对本地库存建立编号索引。Trakt 即使有 3 万条历史，也不逐条查询 MovieClaw；库外记录只计为未匹配，不新增媒体。
- 计划与详情按每块 30 条持久化，每次执行最多处理 5 条；每条写入成功后记录回执。网络、429、5xx 按 Retry-After 和退避重试，仍需网页保持打开。普通 400／404／422 写入失败按单条保留结果，不阻塞剩余记录；Trakt 授权失效会暂停并阻止该账号新活动，宿主权限不足只暂停任务且不撤销 Trakt 连接。
- Trakt 导入使用完整 history，而不是只有最新观看时间的 watched 汇总，因此保留重看。远端扫描前后、确认前检查 watched 活动时间；变化则要求重新扫描。
- 导入有上游源记录幂等键；响应丢失后重放返回原回执版本。状态版本冲突会跳过，不覆盖扫描后用户的新操作。
- 导入扫描前先确认 Trakt 的固定账号 ID；临时查不到时退避重试，缺少有效 ID 时暂停，不写入本地观看记录。同账号重新绑定或修改账号名后仍沿用去重关系。保留原 beta 绑定升级时，会保留已有记录的去重标识；旧版尚未完成的导入预览须取消后重新扫描，已经完成的同步历史继续保留。
- 有旧 beta 导入记录时，断开连接也会先保存旧去重关系，不必先跑一次扫描。接口或存储暂不可用时保留连接，建议稍后重试。若原授权已无法恢复，可在第二次明确确认风险后强制断开；这可能导致以后重新导入时产生重复，本地已有观看记录不会被删除。普通断开和 CLI 的默认请求都不会自动选择放弃去重关系。
- 导出前重核源观看仍存在、当前已看且外部编号与预览一致；编号变化时跳过，需重新扫描确认；提交前分页查询同一 UTC 分钟、同一电影／单集的历史。请求结果不确定时先核对远端再重试。[Trakt #694](https://github.com/trakt/trakt-api/discussions/694) 说明秒／毫秒归零并按项目和时间去重；不同分钟不能混淆，同分钟额外源记录不能分别表示。两端仍无事务，不能承诺跨系统 exactly-once，详见[分钟精度说明](trakt-time-contract.zh-CN.md)。
- 已成功记录不重复推送。远端完全没变化时可跳过全量远端拉取；有变化时仍可能重新分页核对，只跳过已成功项。不能声称所有后续同步都零查询。
- 实时事件的 `watch_source_ids` 与目录观看的 `source_ids` 采用相同日志 ID。插件在移除实时待发任务前保存共同回执；导出读取该回执，避免源时间、远端接收时间、最终停止时间不同造成重复。续播日志共享回执，另一场重看 ID 不同，仍分别处理；成员、绑定代次、冲突的外部编号隔离。同一源的实时任务尚未完成时，导出保留为失败待重试，避免抢先写入；反向先导出再收到迟到实时事件，也使用共同回执。
- 同一分钟被 Trakt 合并的额外观看仍保留本地精确时间的排序保护；旧回执和别名恢复也会补齐该标记。两次观看之间发生的旧取消操作不能删除较新的观看，真正晚于最后一次观看的取消仍会执行；合并项仍按跳过计数。
- 这些关联只覆盖携带共同 ID 的事件及已建立的回执。升级前已经成功发送、且没有源 ID 的旧记录无法凭空补出可靠对应关系，仍只能按现有远端历史和源时间核对；不承诺重建旧来源信息或跨应用绝对 exactly-once。
- 原生实时 scrobble 的时间由 Trakt 分配。响应丢失时使用持久化的实际派发窗口核对，不能按源完成事件的分钟误补一条；明确改为 `/sync/history` 后先持久切换意图，仍按源分钟查重。窗口、进程退出与并发来源的限制见[分钟精度说明](trakt-time-contract.zh-CN.md)。
- 同步手动取消已看前，持久记录成员／电影或单集／绑定代次的截止时间，停止更早的播放待发及失败任务；晚到的旧播放事件也不能将它重新标为已看。手动标记已看的旧失败重试也遵守同一截止时间，已被覆盖的任务显示为跳过。之后的新观看先等待更早的待发取消执行；保存最近成功观看时间，防止晚到旧取消或旧取消重试误删较新的观看。其他单集、成员与新绑定互不影响。
- 再次连接会更换账号代次，旧批次不能继续写入新绑定；历史回执仍供管理员查看。手动改变本地或 Trakt 状态不会自动撤销旧回执；增量同步不保证强制覆盖用户后来的主动修改。

## 验证范围

本地测试使用隔离 SQLite、真实 MovieClaw HTTP 网关和真实插件入口；只有 Trakt HTTP 被模拟。覆盖扫描不写入、确认不自行执行、原时间、三次重看、成员隔离、分别授权、响应丢失去重、限流、源状态改变、分页、3 万条历史／400 个本地单元、重复扫描增量，以及卸载后插件资源释放。浏览器模拟资料验证扫描 → 预览分组 → Confirm → 完成和详情按需加载。

共同 ID 与插件已在正式 v0.44.0 源码上配套验证，NAS 的 v0.44.0 安装也已核对账号、偏好、状态与目录读取。自动化测试未向真实 Trakt 账号写入测试记录；模拟 Trakt 的结果不代表真实账号写入或完整 iPhone 离线重连流程已验收。
