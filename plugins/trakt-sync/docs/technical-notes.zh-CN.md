# 技术与维护说明

## 0.3 正式版

0.3.0 固定验证正式 v0.44.0，要求停止／完成事件 1.1 契约；包含三个默认关闭的实时开关与前台确认历史同步。申请四项宿主操作：两项元数据读取、`playback.sync.catalog` 读取观看事实、`playback.sync.import` 导入已看事实。无文件系统权限。手动操作任务与历史批次采用独立持久化计划，不受下述播放 ledger 容量限制；终态单条错误不阻塞后续操作。详细流程和限制见 [同步说明](sync-workflow.zh-CN.md)。

本目录的安装和更新入口是「设置 → 插件 → 插件市场」，见 [README](../README.md)。不需要用户切换服务器分支。清单申请播放／标记／收藏事件、网络、插件数据及上述四项操作，没有媒体删除或文件访问权限；历史导入由用户扫描、确认后执行。

## 投递、容量与授权

每个成员独立加密保存授权、使用独立锁；Trakt refresh token 轮换后先落盘，临时落盘失败时在内存保存新令牌，不再次兑换已使用的旧令牌。401 会尝试刷新并重放一次；OAuth 刷新的 400 或接口的 401/403 会阻断该成员，网络故障仍按退避重试；单条写入的 400 按媒体匹配失败处理，不清空其他任务。不把授权失效时收到的事件排进队列，不借用其他成员令牌。

队列最多 64 项，整个 ledger 不超过 60 KB；最多 256 个去重 ID、16 个会话和最多 64 个匹配失败记录（仍受总字节数限制）。满时先移除过期的非完成任务，再移除心跳和其他非完成任务，最后才舍弃旧完成任务。确实舍弃播放记录时累计未同步数量，界面提示；可确认清除提示，累计数量保留，不补发。容量提示与连接错误分开，不让历史丢失永久降级 health。容量或授权状态不向可靠消费者抛错。底层持久化故障仍会报错，让宿主按其可靠事件机制处理。

宿主可靠消费者按订阅而非成员共享，不能用某成员的永久满队列去让消费者无限重试。有限队列无法同时保证永不丢失和无限断网，这里明确选择隔离成员、保留近期任务并显示损失。

活动记录独立存储，最多 80 条/48 KB；开始和进度心跳不进入展示，旧版心跳也从读取结果中过滤。记录中不包含令牌、请求正文、设备名或路径。

后台启动时从明文 ledger/linked 做一次任务索引迁移，再逐个读取账号；不通过 scopes(account) 一次解密所有成员。某个账号无法解密不阻断其他成员，损坏成员可清除本地连接后重新授权。旧版只有账号、尚无 ledger/linked 的非管理员绑定，在首次播放或按成员 ID 查看时被发现。意外投递异常按成员独立退避 10～300 秒，不每秒重试刷日志。之后只枚举未加密的 `delivery` 标记，按队首下次执行时间唤醒；无任务时等待新任务，不每 5 秒解密遍历所有账号。账号列表用 `linked` 标记枚举，需要显示时才读取对应成员状态。删除成员前必须先断开 Trakt；没有删除事件可自动回收身份。

## 播放与离线边界

Trakt 是否产生观看记录依其进度阈值；不足 1% 的 stop 返回 422 时按清除 watching 的短播放处理，单条写入的 400 和匹配失败的 404/422 可单独重试。宿主显式 completion 即使 position 清零也会作为完成处理；已看状态本身不把一次未完成重看变成完成。

超过 5 分钟才收到的完成事件按原始 `occurred_at` 写历史；不是把整份已有历史导入。宿主未发出的事件无法还原。代码保留可选 `viewing_id` 扩展路径，但官方载荷不保证提供它，这不是当前承诺的能力，也没有证明完整离线重看链路可用。对不确定完成写入，在附近历史中核对后再重试；跨 Trakt 和本地存储没有分布式事务，仍可能重复。

## 应用与验收

历史写入与不确定结果查重遵循 [Trakt UTC 分钟精度](trakt-time-contract.zh-CN.md)：远端秒／微秒归零，本地 `occurred_at` 与新旧操作排序仍保留原精度。同一分钟额外观看不能分别导出，不同分钟不能用前后 60 秒容差误合并。

默认使用 MovieClaw 项目维护的公开应用，无 Secret 的设备码流程见 [APPLICATION.md](../APPLICATION.md)。源码不放 Client Secret。仅自行部署者可使用自己注册的应用覆盖配置，Secret 由宿主加密保存。换应用前断开旧连接；发现 Client ID 已不匹配时只清除本地绑定，不拿新应用的凭据去撤销旧应用。

## 在此仓库验证

依赖由 MovieClaw 提供，不在 NAS 手动装 pip。使用本仓库 CI 固定的 MovieClaw 源码和 Python 3.12：

```sh
PYTHONPATH=/path/to/MovieClaw/src python /path/to/MovieClaw/src/movieclaw_agent/builtin-skills/movieclaw-plugin-dev/scripts/check_plugin.py plugins/trakt-sync
PYTHONPATH=/path/to/MovieClaw/src python -m unittest discover -s plugins/trakt-sync/tests -t plugins/trakt-sync -v
python scripts/generate_index.py --lint
python scripts/pack.py plugins/trakt-sync --output dist/trakt-sync.mcplugin
```

测试使用虚构凭据和模拟 Trakt 响应，不把它们当成真实授权验收。包、哈希、签名索引均由本仓库发布工作流生成；不要用重新打包的文件去核对别的发行包的哈希。

## 0.2.2 失败恢复

匹配失败任务按 10 分钟至 6 小时退避重新读取本地元数据。新任务保存 media_id/file_id；有 file_id 时只跟随同一文件的当前外部编号与季集，不猜测 S00 应改为哪一季。完成任务在原始时间附近分页核对 Trakt，已存在则不重复推送。无 file_id 的旧任务只支持当前季集匹配或人工修正，不能判断其原文件是否已删除。

已删除的媒体/文件记录停止同步，暂时 missing 或待回收则等待。超过 5 分钟的非完成播放事件过期停止；忽略失败只移除本地待处理任务，不删 Trakt 历史。队首网络退避优先于失败扫描，不造成到期标记忙循环。元数据读取故障不丢任务，10 分钟后重试。
