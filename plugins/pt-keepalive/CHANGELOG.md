# 变更记录

## 0.2.3 (2026-10-29)

修 issue #43：网络失败时日报只说「失败 1」，看不出是哪个站、为什么；临时网络错误
（如 M-Team 的 `ConnectTimeout`）一撞上就把这一轮记成失败，没有第二次机会。

- **日报列出每个失败的站点和原因**。正文在汇总数字之后多一段
  「失败：M-Team：连接 M-Team 失败：连接超时（ConnectTimeout）」——站点用展示名，
  原因是判定层给出的那句话；连续多轮的带上「（连续 N 轮）」，其中凭据失效的站按
  **失效前真实失败过的轮数**计（不再是状态机为触发告警而植入的阈值）。只列「失败」，
  跳过（站点没配好 / 未适配）和需人工（CF 拦截）不算故障，不进这段；但连着坏到阈值、
  本轮却变成跳过 / 需人工的站会补一句「此前已连续失败 N 轮」，免得看起来像好了。
- **明细有上限**：最多列 8 站、正文最多 900 字，超出写「另有 N 站，详见『设置 → 插件』」。
  宿主推送载荷有 2200 字节明文上限，超了会被静默截断——与其发一条末尾丢字的通知，
  不如自己先说清。
- **`DailyReport.failures` 的语义变了**（对 Webhook / 订阅方）：`report.daily` 里现在是
  「本轮全部失败站点（含首次失败、含凭据失效）」，旧版是「连续 3 轮失败、尚未报过的站点」；
  `report.failures` 里仍是后者。字段名相同是因为两条通知共用 `{detail}` 正文。
- **临时网络错误自动重试**：本轮跑完后，本轮判成临时错误的站点按 **1、3、5 分钟**
  退避再各试一次，三次仍失败才记这一轮失败，说明里注明「本轮已重试 3 次仍失败」。
  重试按整轮统一进行（只重打失败的那几个站），等待总时长不随站点数增长
  （最坏一轮约 10 分钟，默认每天一次不受影响；把周期改成分钟级时要注意）。
  - 算临时错误的：网络层失败（超时、连不上、连接被重置、代理失败）与宿主的 5xx
    （`site.proxy.request` 把站点超时 / 连不上统一回 503），以及站点自己的 5xx。
  - **不算的**：凭据失效、登录被拒、两步验证密钥填错、站点改版（签名轮换）、限流、
    4xx 参数错误。登录失败会消耗账号尝试次数，重试只会白挨一次风控。
  - M-Team 更细一层：连不上（`ConnectError` / `ConnectTimeout`）可重试；登录请求**发出后**
    才超时（`ReadTimeout` / `WriteTimeout`）不可重试——站点可能已经处理过；登录阶段收到
    网关 5xx 可以重试（网关回话说明登录接口没执行过）。
- **Cloudflare 拦截页不再被当服务端故障重试**：challenge 特征现在先于 5xx 判定，
  CF 常把拦截页挂在 503/520 上，此前会被当成故障连打 4 次。
- **M-Team 网关 5xx 现在会被判成可重试的服务端故障**：此前非 JSON 正文一律落到
  「站点返回未预期的响应：（空）」，既没有状态码也不重试。
- **网络错误写成「连接超时（ConnectTimeout）：…」**：常见 httpx 错误
  （ConnectTimeout / ReadTimeout / WriteTimeout / PoolTimeout / ConnectError / ReadError /
  RemoteProtocolError / ProxyError / NetworkError）各有中文说法，同时保留原始类名与异常原文
  （证书、DNS、代理的细节都在原文里）。
- 单测 139 个全绿（新增 26 个：日报列出失败站点与原因、连续轮数标注、失效轮数不被植入值
  污染、跳过站不丢历史失败、明细上限与字节上限、临时错误重试到成功 / 三次仍失败 /
  凭据失效不重试 / 4xx 不重试 / 只重打失败的站、重试完不再标可重试、M-Team 登录阶段
  各错误的重试语义、网关 5xx、CF 拦截页优先、网络错误文案表与 fallback）。

## 0.2.2 (2026-10-25)

**移除插件设置里的「每天发保活日报」开关**。它和「账号 → 通知」里
「插件 · PT 站点保活 → PT 保活日报」的开关管同一件事、互相不知道：两边都开才有日报，
关掉任何一个都静默无声——两个开关问的是不同层面的问题（事件发不发 / 这个人收不收），
但「发不发」对日报没有意义，宿主的通知模型里也不该有这一层。

- 日报现在每轮都发布，**收不收只看「账号 → 通知」里的开关**（默认关，打开后每天一条）。
  那里现在是唯一的日报开关；插件设置里不再有重复项。
- 以前在插件里开过日报的：到「账号 → 通知」打开「PT 保活日报」即可，旧设置值不用清理
  （插件已不读这个字段）。
- **连续失败升级告警不再依赖日报开关**。以前日报开着就不发升级（失败明细只在日报里），
  现在两条独立发布：升级照旧「同一段失败只报一次」、level=active，日报每天一条被动汇总。

## 0.2.1 (2026-10-23)

适配宿主 `site.proxy.request` 不再跟随站点 3xx 跳转的新行为。宿主这样改是为了防认证头
（`x-api-key` 等）经站点的开放重定向被带到外站：站点回 3xx 时，宿主原样返回
`{"status_code": 302, "headers": {"location": "..."}, "text": ""}`，要不要跟由插件决定。

- **修正：登录跳转不再丢「凭据失效」告警**。NexusPHP 站会话失效时，`index.php` /
  `attendance.php` 会 302 到 `login.php`。以前宿主跟随跳转、拿到登录页 HTML，密码框命中
  才判失效；宿主不再跟随后插件只看到一个空正文的 302，会落到「页面未见登录证据，无法确认
  会话有效」——判失败、但**不**置 `auth_expired`，告警就静默丢了。现在 `Location` 的路径
  带 `login`（`login.php` / `takelogin.php` / `/login`）直接判凭据失效，说明是「站点跳转
  到了登录页，凭据已失效」。只看路径，不看查询串；也不要求同站——`Location` 可能是相对
  路径（`/login.php?returnto=...`）也可能是绝对 URL，跳去登录页本身就是会话失效的证据。
- **同站跳转照常跟**：`Location` 是相对路径，或绝对 URL 且主机与站点一致，就对那个站内路径
  （路径加查询串）再发一次 GET，最多跟 3 跳。尾斜杠、`attendance.php` → 带查询串的同站
  路径都在内；绝对 URL 只比主机，不比协议和端口（`Location` 写成 `http://` 的同站地址也
  照跟，请求仍按宿主注册的地址发）。站点域名取自 `site.catalog` 的 `base_url`（插件本来就读
  这个操作拿展示名，不新增权限）；拿不到目录时只跟相对路径的跳转。
- **不跟的一律记失败并写明原因，不置凭据失效**（一个跳转不足以断定凭据失效）：跳到别的
  主机（说明里带上主机名；裸域与 `www.` 互跳也算别的主机）、跳转成环、超过 3 跳、没有
  `Location`、拿不到站点域名时的绝对 URL。宿主只收站内相对路径，跨主机的跳转没有任何办法
  替站点跟下去。只跟 GET；POST 遇 3xx 同样不跟（当前所有步骤都是 GET）。
- **成环按「同一个跳转第二次出现」判，不按「到过同一页」判**：做完动作再跳回同一页、或跳去
  `cookiecheck.php` 设个 cookie 再跳回来，第二次到那一页拿到的才是真页面，宿主以前跟随时
  这些都能过，插件不能把它们误判成环；真正的环由「同一个从哪跳到哪」重复来抓，兜底是 3 跳
  上限（一个步骤最多 4 次请求）。
- 对仍会自己跟随跳转的旧宿主没有影响：插件看不到 3xx，行为和之前一样。
- 单测 113 个全绿（新增 28 个：登录跳转的各种写法与它不依赖站点域名、相对 / 绝对 / 协议
  相对的同站跳转与各 3xx 状态码、跨主机的几种构造（`evil.example`、`hdsky.me.evil.example`、
  `hdsky.me@evil.example`）、成环与「跳回同一页不算环」、3 跳可过 / 4 跳被拒、无 `Location`、
  POST、站点域名的来源）。用假站点 + 真宿主做了端到端（打包安装、批准、进程外运行、诊断页、
  卸载重装），见 `docs/pt-keepalive/04-acceptance.md`。

## 0.2.0 (2026-10-20)

M-Team 改为「账号密码 + TOTP 登录」保活（与调研选定的 mtlogin 路线一致），
不再拿宿主的 API Key 去调它的保活接口。

- **修正**：上一版用宿主 `site.proxy.request` 带 API Key 调 `/api/member/updateLastBrowse`，
  真实站点一律回 `{"code":401,"Full authentication is required..."}`——这个接口只认网页会话
  JWT，API Key 只能读（`/api/member/profile` 正常）。原实现会把这一站每轮判成「凭据失效」。
- 新增 `pt_keepalive/mteam.py`：按站点前端的行为发 `POST /api/login`（账号 + 密码 + 空
  turnstile），`code 1001` 时补 TOTP 动态码重发，取响应头的 `Authorization`（JWT）与 `Did`；
  随后 `profile` 验会话、`updateLastBrowse` 刷新。签名 `_sgin` 用 HMAC-SHA1，TOTP 用标准库
  自算（不引入 pyotp）。
- 插件设置新增三个 M-Team 字段（账号 / 密码 / 两步验证密钥），密码与密钥是 `SecretStr`，
  宿主 SecretBox 加密落盘、界面不回显；留空即不做这一站。
- 登录态（JWT + 设备指纹）存插件数据（`secret=True`）跨轮复用：少走登录（登录失败会扣账号
  尝试次数），并保住服务端认可的 `Did`。
- **判定修正**：`updateLastBrowse` 的 `{"code":"1","message":"FAIL"}` 是「站点认为无需刷新」
  （间隔过短 / 已被别的工具刷新），记「登录在线」而不是「成功」——它确实没刷新；
  也不算失败。签名错误（「簽名錯誤」）与限流（「請求過於頻繁」）不置 `auth_expired`。
- 清单声明 `network = true`：M-Team 的请求由插件直连 `api.m-team.io`（其余站点仍经宿主代
  请求）；插件出口跟随用户在「设置 → 网络」给 `pt-keepalive` 配的代理。
- **借不到宿主会话时不再一声不吭**：站点在宿主那边没验证通过（典型的成因是站点开了两步
  验证、而宿主的账号密码登录带不上动态码）时，本轮记「跳过」并把宿主给的原因原样写进结果，
  附上「改用 Cookie 方式即可绕开」的提示；正在验证中的站点（pending/verifying）另说一句
  「还在验证中」，不渲染成故障。两类都不发失效告警。
- **登录方式的选择写进 README**：NexusPHP 站由用户在「设置 → 站点」自选 Cookie 或账号密码；
  开了两步验证就选 Cookie（宿主从不访问登录页，因此永远不会碰到动态码）。插件只在宿主
  凭据根本做不了保活时（目前只有馒头）才自己登录——这条边界是刻意的，见 README
  「插件什么时候才会自己登录」。
- 单测 85 个全绿（假响应，不连站点）：签名算法、RFC 6238 的 TOTP 向量、各失败形态的分类、
  登录→刷新流程、会话复用、无人值守时的「无需刷新」判定、网络错误与签名轮换的告警分级、
  宿主未验证通过与验证中两种跳过的说法。

## 0.1.1 (2026-10-20)

装到 MovieClaw v0.39.0（NAS/Docker）前与安装时的修正：

- 入口模块不再从 `movieclaw_api.plugins.keys` 导入 `PLUGIN_DATA` / `PLUGIN_ROUTES`：
  插件包在独立进程里只有 `movieclaw_sdk` 在导入路径上，原来那样写会让插件起不来。
  改为在插件侧按同名同版本造 `ServiceKey`（服务按名字 + 版本认）。
- 站点适配分派按大小写不敏感比对 `auth_type`：宿主 `site.list` 回的是枚举值
  `APIKEY`，原来只认小写 `apikey`，会把 API 站误判成 NexusPHP 站。

## 0.1.0 (2026-10-18)

首个版本。

- 每日定时对已配置且验证通过的 PT 站点跑一轮保活：NexusPHP 系先访问 `index.php`
  确认登录态、再访问签到页 `attendance.php` 尝试签到（可整体关闭签到，只做登录确认），
  没有签到页的站点（404）不算失败。
- 四态结果判定（签到成功 / 仅登录在线 / 失败 / 需人工），外加「跳过」表示本轮未访问：
  判据来自社区项目（MoviePilot autosignin、flexget_qbittorrent_mod）的成熟经验——
  先剥脚本与隐藏元素再匹配证据、登录失效证据优先、人机验证与 WAF 拦截判「需人工」、
  未知响应保守判「仅在线」。
- 未适配的纯 API 站点（如 sunnypt）本轮跳过、不发请求，也不进失败统计。
- 凭据失效发通知（同一失效期只告警一次，告警发送失败下一轮自动重试），
  恢复后自动清零；连续 3 轮失败的站点进日报明细。日报通知默认关闭。
- NexusPHP 站点的请求经宿主的 `site.proxy.request` 操作代发：复用宿主登录态、
  每站限流与代理出口，插件全程接触不到凭据。
- `mclaw plugins pt-keepalive status` 查看各站最近一轮结果。
