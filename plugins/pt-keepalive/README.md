# PT 站点保活（pt-keepalive）

对宿主里已配置且验证通过的 PT 站点，每天跑一轮保活：访问首页确认登录态、尝试签到
（可关）、M-Team 刷新「最后活跃时间」。两类站点走的路不同：

| 站点类型 | 动作 | 凭据 |
|---|---|---|
| NexusPHP（hdsky、chdbits 等） | GET `index.php` 确认登录态 → GET `attendance.php` 尝试签到 | 用宿主已配置的会话代发，插件接触不到 |
| M-Team（`mteam`） | 账号密码 + TOTP 登录 → POST `/api/member/profile` → POST `/api/member/updateLastBrowse` | 插件设置里填（宿主 SecretBox 加密） |
| 其余纯 API 站（如 sunnypt） | 不访问 | — |

## 插件什么时候才会自己登录

**只有一种情况：宿主手里那套凭据根本做不了保活。** 目前只有馒头（M-Team）符合：

- 宿主给馒头存的是 **API Key**，而它的保活接口只认网页会话——同一个 Key 调
  `/api/member/profile` 正常返回 `code:"0"`，调 `/api/member/updateLastBrowse`
  一律回 `{"code":401,"message":"Full authentication is required..."}`（2026-10-20 实测）。
  宿主没有第二条路可走，所以这一站由插件按社区方案
  [scjtqs2/mtlogin](https://github.com/scjtqs2/mtlogin) 的做法，用**账号密码 + TOTP 动态码**
  自己登录拿 JWT；登录态（JWT + 设备指纹）存插件数据加密保存，下一轮复用。

**其余站点一律借宿主的会话**，插件不登录、也拿不到凭据。这是刻意的：

- 宿主自己会维护站点的登录态（Cookie 过期它会重新登录、重新验证），插件再登一次就是
  两套会话对着同一个账号，容易互相把对方顶掉；
- 插件的凭据存储能力远不如宿主（宿主有加密表、验证状态机、代理出口、每站限流），
  在插件里再存一份密码只会多一个要同步的副本。

### 站点开了两步验证怎么办

NexusPHP 站的登录方式是在「设置 → 站点」里自己选的，和三件事有关：

| 你选的方式 | 宿主会做什么 | 会碰到两步验证吗 |
|---|---|---|
| **Cookie**（浏览器复制一串字符） | 直接把这段字符用在请求上，**从不访问登录页** | **不会** |
| **账号密码** | 第一次要替你登录；成功后把会话存下来复用 | **会**（仅限登录那一次） |

所以：**站点开了两步验证，就选 Cookie 方式**。搜索、下种、保活全部照常走，唯一代价是
Cookie 过期后要你重新从浏览器复制一次（一般几周到几个月）。

如果选了账号密码而站点又开了两步验证：宿主的验证会失败（它登录时带不上那 6 位动态码），
该站在插件里会记「跳过」并把宿主给的原因原样带上，同时提示改用 Cookie——
**不会误报成「你的账号失效了」**。

> 让宿主自己也支持动态码（在站点配置里填 TOTP 密钥）是一条更彻底的路，但那要改主程序。
> 本插件的定位是「主程序做不了的事才在插件里做」，所以没走这条路。

## 它做什么

- **凭据不出宿主（NexusPHP 系）**：这些站点的请求经宿主操作 `site.proxy.request` 用宿主
  自己的已认证会话代发，插件接触不到 Cookie / API Key。
- **站点的跳转自己判**：宿主代请求**不跟随**站点的 3xx（否则认证头会经站点的开放重定向
  被带到外站），原样回 `Location`，由插件决定：
  - 跳到登录页（路径带 `login`：`login.php`、`takelogin.php`……）= 会话失效，按凭据失效
    告警——NexusPHP 站会话失效时 `index.php` / `attendance.php` 就是这样 302 到 `login.php`；
  - 同站的跳转（相对路径，或主机与站点一致的绝对 URL——绝对 URL 只比主机，不比协议和端口；
    尾斜杠、带查询串的同站路径都算）再发一次站内路径的 GET，最多跟 3 跳；
  - 其余（跳到别的主机、成环、超过 3 跳、没给目标地址）记失败并写明原因，**不**发失效告警。
    「成环」指同一个跳转（从哪跳到哪）第二次出现；做完动作跳回同一页、跳去设个 cookie 再
    跳回来，第二次到那一页拿到的才是真页面，照常跟。
- **不虚报**：签到成功、仅登录在线、失败是三种不同结果，页面证据不明时保守判「仅在线」。
  人机验证 / WAF 拦截记「需人工」，不算失败也不发失效告警。
- **M-Team「无需刷新」不算失败**：站点认为间隔过短、最后浏览时间已经新鲜时回
  `{"code":"1","message":"FAIL"}`——此时它**没有**刷新，但也不是账号失效。记「登录在线」，
  不进失败统计（本机还跑着 mtlogin 容器时，每轮都会撞上）。
- **签名错误的处置**：签名密钥来自站点前端 JS，站点发版轮换后请求会被回「簽名錯誤」。
  这时记失败并提示「插件需要更新」，不当成用户凭据失效去打搅。
- **不自动重登 NexusPHP**：PT 站普遍禁止脚本登录，失效只通知用户去「设置 → 站点」更新凭据。
- **借不到会话就说清楚**：站点在宿主那边没验证通过时本轮跳过，并把宿主给的原因写进结果——
  分得清「刚配好还在验证」和「凭据真的不行」，不会一声不吭。

## 设置

插件详情页：

- `enabled` — 总开关。关闭后定时任务照常触发，但跑空轮、不访问任何站点。
- `signin_enabled` — 尝试每日签到。关闭后只确认登录态，不请求签到页。
- `daily_report` — 每天发保活日报。凭据失效告警不受它控制，始终发。
- `mteam_username` / `mteam_password` / `mteam_totp_secret` — M-Team 登录信息（密码与
  TOTP 密钥加密保存、界面不回显；留空即不做这一站）。

周期不在设置里：「设置 → 定时任务」里的 `PT 站点保活轮`（默认每天 09:17）可以改。

## 通知

| 事件 | 默认 | 内容 |
|---|---|---|
| `pt-keepalive.auth.expired` | 开（active） | 「{站点} 登录已失效」；同一失效期只发一次，恢复后清零 |
| `pt-keepalive.report.daily` | 关（passive） | 在线 / 签到成功 / 失败 / 需人工 / 跳过各多少站；连续 3 轮失败的站点带明细 |
| `pt-keepalive.report.failures` | 开（active） | 有站点连续 3 轮失败（每段失败只报一次） |

## 状态查询

```bash
mclaw plugins pt-keepalive status
```

返回每站最近一轮的结果、说明、连续失败数、上次成功时间。

## 前置条件

宿主必须提供 `site.list`、`site.catalog`、`site.proxy.request` 三个宿主操作
（`site.proxy.request` 随主程序的新版本提供）。旧宿主上插件照常加载但不注册定时任务，
日志会说明需要升级主程序。

`site.proxy.request` 在新版宿主里不跟随站点的 3xx，上面「站点的跳转自己判」就是为此；
自己跟随跳转的版本也能用，插件那时根本看不到 3xx。

M-Team 的请求直连 `api.m-team.io`，与宿主会话无关；插件声明了 `network = true`。
需要走代理时，在「设置 → 网络」给 `pt-keepalive` 配代理即可（与其它插件同一套出口）。

## 已知限制

- **M-Team 依赖站点前端的签名算法与版本号**：签名密钥（`HLkPcWmycL57mfJt`）、
  `version=1.1.4` / `webversion=1140` 都可能随站点发版变化；变了会以「签名错误」或异常
  响应暴露出来，改 `pt_keepalive/mteam.py` 顶部的常量即可。
- **站点改走强制 Turnstile 人机验证后**账号密码模式会失效（mtlogin 也一样），届时只能手工
  透传 JWT，插件暂不支持。
- 适配分派按 `auth_type` 大小写不敏感比对（宿主 `site.list` 回的是枚举值 `APIKEY`）。
- **跳转只跟同站**：宿主只收站内相对路径，插件没法替站点跟到另一个主机。站点把宿主注册的
  域名跳到另一个（裸域 ↔ `www.`、换了新域名）时，这一站每轮记失败，说明里写着跳去了哪个
  主机；要在宿主的站点配置里改成站点现在的地址，插件这边解决不了。站点域名取自
  `site.catalog` 的 `base_url`：拿不到目录（没有该权限等）时只跟相对路径的跳转；自定义站点
  若把网页域名 `web_base_url` 配得和它不同，也会被当成跳到别的主机。宿主还是按注册的地址
  （含 `http` / `https`）访问：注册成 `http://`、而站点强制跳 `https://` 时，跳转落回同一个
  路径，会被判成环——把宿主里的站点地址改成 `https://`（内置站点都已经是）。

## 风险

程序化签到 / 访问未必被站方计为「用户活跃」，插件显示成功只代表请求与判据成立，
**不承诺免于封号**。M-Team 的账号密码登录属于脚本登录，站点规则敏感的用户可以只在
宿主里保留 API Key、不填插件里的 M-Team 账号（其余站点照常保活）。
