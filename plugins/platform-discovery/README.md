# 映屿 · Yingyu

<img src="web/icon-color.svg" width="80" height="80" alt="映屿图标">

属于你的电影小岛。

MovieClaw 的海报发现与媒体库浏览插件。提供按账号同步的推荐海报墙、库存录像厅、平台片单和地区剧集探索；无需修改主程序。当前版本 **0.2.1**，兼容独立入口，并为 **MovieClaw Server 0.41.0** 提供正式原生菜单适配。完整操作见 [使用教程](docs/USER_GUIDE.md)。

Yingyu (formerly Platform Discovery) adds an account-scoped recommendation wall, a library theater, platform feeds and regional TV discovery to MovieClaw. It runs as an explicitly approved inline plugin. It does not modify the host application. The plugin UI and documentation are currently in Simplified Chinese.

## 四个页面

| 页面 | 功能 |
| --- | --- |
| 海报墙 | 口味测试与历次偏好、喜欢／已看过／稍后看／不感兴趣，国家与年代多选、题材包含与排除、探索程度、收藏筛选方案、浏览历史与撤销。 |
| 录像厅 | 只显示当前账号有权访问的库存；按电影／剧集、媒体库、合集及更多条件筛选，查看季集，并跳转 MovieClaw 原生播放。 |
| 平台热榜 | Netflix 官方周榜与自动检查；国内平台官方公开片单；HBO Max、Disney+ 等地区片库。每种来源明确标注，不把推荐顺序或地区片库称作播放量榜。 |
| 随心看剧 | 韩剧、华语剧、日剧、美剧、英剧、泰剧等地区随机推荐，覆盖新旧作品。 |

海报详情可查看简介与参演资料。电影和剧集均可在插件内预检订阅；剧集可选季，只有点击确认后才创建订阅，沿用宿主已有的订阅策略和入库路由。不会因浏览、悬停或预加载而自动订阅。

## 安装与打开

1. 从维护者发布的 Release 下载 `.mcplugin` 文件。在 MovieClaw **设置 → 插件 → 上传插件包** 上传，审阅后批准。
2. 本插件是 `runtime = "inline"`，**与 MovieClaw 主进程共享系统权限**，不是独立进程沙箱。账号同步、库存访问和直接订阅使用宿主内部模块与登录依赖，需要单独确认 inline 权限。
3. 进入插件设置按需填写网络及资料来源。直接在已登录的服务器上打开：

   ```text
   /api/v1/plugins/platform-discovery/panel?view=personal
   ```

   可在当前 MovieClaw 地址后附加上述路径；不同 IP／域名均跟随当前来源，未登录时先登录并返回插件。源码的 HTML 文件不能脱离服务器直接作为在线页面使用。
4. MovieClaw 0.41.0 起，主程序只保留一个「映屿」入口。进入后在页内切换海报墙、录像厅、平台热榜和随心看剧；下表是可收藏的板块地址，并非四个主程序菜单：

   | 页内板块 | 地址 |
   | --- | --- |
   | 海报墙 | `/apps/platform-discovery/` |
   | 录像厅 | `/apps/platform-discovery/theater` |
   | 平台热榜 | `/apps/platform-discovery/platforms` |
   | 随心看剧 | `/apps/platform-discovery/random` |

   电脑在主导航，手机浏览器在「我的」页；导航排序及隐藏由主程序管理。网页信任必须由管理员在网页确认，普通成员是否可见由管理员选择。旧版宿主仍可使用独立入口。插件不会注入或改写宿主前端。
5. 原生页只有宿主的一层 iframe，资源均使用同源绝对路径；刷新、地址回跳和前进后退保持板块。字体、按钮和颜色跟随宿主主题；电脑显示四项页内导航及说明，手机使用紧凑切换条。

管理员可用已配对的 CLI 上传安装包：

```sh
mclaw app plugins packages upload --file platform-discovery-0.2.1.mcplugin
```

然后回到 MovieClaw 网页的「设置 → 插件」审阅并批准本版本的主进程运行、网页信任及菜单可见性。不要让代理或命令行代替网页信任确认。安装后可用 `mclaw app plugins show platform-discovery` 查看状态。

## 升级与数据保留

从正式统一编号的 0.1.0 升级至 0.2.1，无需卸载或重新配置。内部 ID、权限、账号偏好、片单和缓存格式保持不变，先备份服务器数据并保留原安装包，再上传并批准新包。

历史 0.11.0 / 0.11.1 已撤回商店推荐，原标签和附件保留。如果仍安装这些旧编号，0.2.1 的语义版本小于 0.11.1，需要手动上传并批准切换，商店不会将其提示为普通升级；切换时无需清空数据。不要使用开发早期的同名测试包。

## 配置

| 设置 | 说明 |
| --- | --- |
| 代理模式 | `host` 跟随宿主；`direct` 直连；`custom` 仅为本插件使用独立代理。 |
| 普通／认证代理地址 | 地址必须从**服务器或容器内部**可达；`127.0.0.1` 指服务器或容器自身。带认证信息的地址使用秘密字段。 |
| TMDB Read Access Token | 可选但建议配置，提升独立资料与推荐取片能力；留空使用可用的宿主发现接口兜底。 |
| Fanart.tv API Key / Personal Key | 可选；未配置时仍使用 TMDB 海报，不保证每个作品都有 Fanart 海报。 |
| 地区、平台开关 | 控制地区片库和可见平台，数据随来源实际可用性变化。 |
| 榜单缓存与自动检查 | 默认缓存 60 分钟、每 60 分钟检查。Netflix 按官网实际发布的最新统计周显示，不制造尚未发布的新周。 |
| 录像厅海报缓存 | 默认上限 2048 MB，仅管理插件自己的服务器缓存；保留宿主全局图片缓存及代理设置。 |

普通代理地址为便于核对会明文显示；含用户名密码的地址应填写到带认证的秘密字段。Token、Fanart 密钥及认证代理都只用于服务器请求，不写进网页或分享包。

## 账号同步与数据边界

- 通过 MovieClaw 已验证的 `Principal` 区分管理员和成员，不信任浏览器传来的用户名来决定数据归属。库权限、分级限制与播放访问仍由宿主核对。
- 同一服务器同一账号跨设备／局域网／公网同步口味测试、片单、已看过、喜欢、筛选、方案、撤销、历史和屏保节奏。不同域名需要各自登录；这是同一台服务器的同步，不是跨服务器云同步。
- 私人记录使用现有插件数据存储的加密账号作用域；公开片目缓存不含个人答案、向量、历史和推荐理由。旧浏览器档案只在本人登录后进行一次性认领合并。
- 已看过、不感兴趣、已收藏／已订阅等身份排除在新片单与缓存恢复时继续执行；关闭行为学习也不会取消已看过排除。管理员同步的是宿主允许看到的订阅范围，不声称它只代表管理员本人创建的记录。
- 动效、全屏、拼贴外观与图片预载是本设备显示选项，保存在浏览器。网络设置、密钥及偏好不包含在安装包中。
- 推荐是基于问卷与行为的可解释加权规则，不是准确率保证。候选不足时明确标记循环补充，不承诺无限次换面均不重复。

## 海报、屏保与有界缓存

普通墙的评分角标仅在悬停、可见键盘焦点或触屏快捷操作展开时显示，支持圆角卡片和可选无缝拼接。全屏默认关闭；一键优先进入浏览器原生全屏；不允许原生全屏时铺满窗口，并提供重新进入按钮。浏览器退出原生全屏后仍保留窗口屏保，明确退出才恢复普通页面。海报墙自动选择完整行列，海报保持 2:3，最后一行不被裁掉。比例不能刚好容纳整数张时居中留边。全屏动效是轻微靠近／远离视线的纵深呼吸，不沿屏幕 Y 轴移动，遵循系统减少动态效果。

全屏下静置 5 秒启动屏保，每轮随机选择 1～3 张与随机位置，以错落时间更替，不固定按 1／2／3 循环。支持旧图尚未消失时新图交叠浮现，以及每张时长与间隔的小幅随机变化，最多六张同时处于变化阶段。交互、详情弹窗、切换页面或隐藏页面会暂停。新图准备失败时保留原海报；轮替使用和手动“换一面”相同的有界候选。只有实际显示才确认展示历史，预载不算已展示。

### 调整屏保节奏

从海报墙「更多设置 → 屏保节奏」，或全屏工具栏的「屏保节奏」进入。读取设置不占普通页面冷启动的网络路径；打开设置暂停轮替，关闭后静置五秒恢复。点击「保存节奏」后按当前 MovieClaw 账号保存，下次在其他设备打开全屏或节奏面板时读取；「恢复默认」先恢复草稿，仍需保存。

| 项目 | 范围 | 默认 |
| --- | --- | --- |
| 淡出时长 | 0.6–6 秒 | 2.0 秒 |
| 淡入时长 | 0.6–6 秒 | 2.6 秒 |
| 海报更替间隔 | 0.2–5 秒 | 0.8 秒 |
| 画面交叠 | 0–80% | 60% |
| 节奏变化幅度 | 0–45% | 25% |

时间是基准值；变化幅度控制每张海报在基准附近的随机偏移。间隔越小，交叠越丰富；网络准备和服务端确认可能使实际启动时间更长。交叠为 0% 时先淡出再淡入，变化为 0% 时固定节奏。账号版本冲突会阻止覆盖另一设备的新设置。仅实际插入的海报计入展示记录，中途打断未显示的候选仍保留。

| 数据 | 上限／策略 |
| --- | --- |
| 一面海报 | 自适应 3–96 张。 |
| 待展示候选 | 每页面最多 3 面；每账号最多 4 个页面队列，服务端票据约 5 分钟过期。未消费候选可继续用于换面。 |
| 浏览器预热 URL | LRU 最多 384 个；后台图片最多 3 个并发，不等待整面图片完成才渲染。节省流量／低速模式会跳过可选预热。 |
| 避重历史 | 最近 40 面；候选不足时先用较早记录。 |
| 录像厅海报 | TMDB／Fanart 按作品身份选择、可手动锁定，服务器本地持久缓存；容量不足优先清理未锁定旧图。 |

缓存不是离线影视库；首次速度依赖用户服务器到资料接口与图床的连接。图片不可达时显示片名占位并提供回退。插件不绕过平台付费播放、登录限制或内容授权。

## 兼容性与限制

- 基础功能以 MovieClaw Server **0.40.0** 为基线；原生菜单适配 **0.41.0**。SDK／`host-ops`／`plugin-routes`／`plugin-data` **1.0**；其他主程序版本需要重新验证。
- 清单申请 `discover.get-title-details`、`discover.filter-titles`，路径授权为空，声明联网。**清单中的两个只读操作不等于 inline 插件只有这两项能力**：inline 与宿主共享权限，必须一起审阅库存、账号和订阅路由实现。
- 国内公开接口可能变更、限流或返回空片单；显示来源状态与缓存时间，不以假榜单替代。TMDB 地区片库不等同于各平台官方热播榜。
- 手机验证使用浏览器视口模拟，未宣称已覆盖所有手机实机。后台标签页计时会受浏览器节流限制。
- 本插件不是媒体播放器；库存播放跳到 MovieClaw。宿主资料服务异常时，新订阅仍可能不可用，不修改宿主网络设置来绕过故障。

## 开发与检查

修改页面后先运行 `python3 tools/build_web.py`，原生静态页由独立页生成；测试会检查两者同步。原生菜单解析需在 0.41.0 环境验证，旧版环境中该项会跳过。

在与仓库 CI 相同的 MovieClaw 0.40.0 环境中运行：

```sh
python3 /path/to/MovieClaw/src/movieclaw_agent/builtin-skills/movieclaw-plugin-dev/scripts/check_plugin.py plugins/platform-discovery
python3 -m unittest discover -s plugins/platform-discovery/tests -t plugins/platform-discovery -v
```

前端行为测试（Node.js，无需真实网络或账号）：

```sh
for test in plugins/platform-discovery/tests/*.cjs; do node "$test" || exit; done
```

使用本仓库可重现打包脚本：

```sh
python3 scripts/pack.py plugins/platform-discovery --output /tmp/platform-discovery-0.2.1.mcplugin
```

测试覆盖账号隔离、版本冲突、缓存与图片失败、预载不计展示、轮替取消、完整视口、选季及显式订阅确认。测试中的凭据、代理和账号均是虚构夹具，不包含运行实例的数据。版本演进见 [CHANGELOG.md](CHANGELOG.md)。
