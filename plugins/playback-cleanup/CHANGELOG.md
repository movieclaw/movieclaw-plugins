# 续播进度清理

## 0.1.3 - 2026-11-09（测试版，需要配套的新宿主）

- 只清 `position_ms` 时，没看完（`played=false`）的片仍留在首页「接下来继续」：宿主锚点按
  `last_played_at` 取。配套宿主改动新增 `playback_state.continue_dismissed`；catalog 行带
  `continue_dismissed` 时，插件写回同时带 `dismiss_continue=true`，整部作品从「接下来继续」（含本设备条）
  消失，不当已看、不跳下一集、不动已看 / 播放次数 / 收藏 / 最近播放时间 / 播放流水。再播放后宿主清掉标记，
  卡片回来，之后还能再清。
- 旧宿主（catalog 没有 `continue_dismissed`，含现有 0.49.1）：只清进度，**不发送** `dismiss_continue`
  （防 `extra=forbid` 整批 422），请求形状与 0.1.2 逐字段一致；结果、扫描说明和清理记录里明确提示
  「宿主不支持隐藏『接下来继续』」。
- 进度已是 0 但仍会出现在「接下来继续」的单元（没看完、播过、未隐藏，比如 0.1.2 清过的）：新宿主上兜底扫描、
  手动清理与播放结束事件都会补上隐藏。看完了的、从没播过的、已隐藏的不动。
- 清理记录多存 `dismissed` / `prior_dismissed`；撤销恢复进度并把 `dismiss_continue` 写回清理前的真实值，
  仍走 `expected_updated_at` CAS（之后又播过即冲突，拒绝撤销）。0.1.2 及以前的记录撤销时不带新字段。
- 按宿主 MovieClaw#1246 的作品级规则调整（需要带 #1246 最新改动的宿主）：宿主只接受落在作品当前锚点
  （`last_played_at` 最大的那一行，平局按 id）上的 `dismiss_continue=true`，否则整条 change 回 `conflict`
  并回滚（`position_ms=0` 也不写）。现在同一部剧只对当前集带 `dismiss_continue=true`，较旧的集只清进度、
  不带该字段（请求形状与旧宿主一致），不再每次扫描都冲突；旧集进度已是 0、或作品已隐藏时不再处理。
  catalog 不给状态行 id，平局时取季 / 集号大的那集。电影 / 视频不受影响。
- 隐藏写入冲突（期间别的设备播过、当前集变了）：重读这部作品一次，按最新 `last_played_at` 重算当前集再试一次；
  仍冲突记为冲突并说明原因，不会退化成只清进度却当成已隐藏。之后的真实播放由宿主自动恢复卡片，插件不发
  `dismiss_continue=false`。
- 只清进度的旧集不存 `dismissed` / `prior_dismissed`，撤销也不带该字段；撤销隐藏时宿主回冲突（之后又播过、
  当前集变了）照旧拒绝撤销。
- identity 令牌、CAS 只重试一次、身份变动即停、只预览 / 未选择不写、权限：均与 0.1.2 相同。

## 0.1.2 - 2026-11-09

- 适配 MovieClaw v0.49.0（#1203）的本地条目身份令牌：两个外部编号（TMDB / IMDb）都没有的条目，
  写回 `playback.sync.state` 时带上 catalog 当时下发的 `media.identity`（= 条目的 `external_id`），
  不再只凭条目 id + 类型。删除条目 A、再建 B 复用同一数字 id 时，带 A 的令牌会被宿主拒为「身份不符」，
  不会把 A 的进度写到 B 上。
- 只有 catalog 行带非空 `identity` 时才发送该字段；旧宿主（v0.46–0.48，`SyncChangeIn` 为 `extra=forbid`）
  的 catalog 没有这个字段，请求形状与 0.1.1 完全一致，不会整批 422。有外部编号的电影 / 剧集仍只带吻合的编号。
- 清理记录保存这次实际使用的令牌；撤销只回放记录里的令牌，不再查 catalog。0.1.1 留下的、没有令牌的
  本地条目记录标为「无法安全撤销」，不发任何请求（有外部编号的旧记录照常可撤销）。
- compare-and-set 冲突仍只重试一次；重读后若条目身份（类型、外部编号或令牌）变了，不改用新身份再写，
  记为「身份不符」。
- 页面「清理记录」：撤销遇到身份不符时如实提示；不能安全撤销的旧记录显示原因。

## 0.1.1 - 2026-11-05

- 支持无 TMDB / IMDb 编号的本地条目与「其他」视频库：没有外部编号的条目只凭条目 id + 类型写回
  （不再跳过成「无 TMDB/IMDb」）；读 catalog 时带 `kinds=movie,tv,video`，「其他」库的 `video` 条目也能清，
  按电影处理（单一 0/0 单元）；播放结束事件也接受 `video`。有编号的条目照旧带上吻合的编号。
- 需要宿主含 local-null sync 补丁（后续正式版）。在旧 0.46.0 上：catalog 不认 `kinds`，插件自动退回只看
  电影 / 剧集；对无编号条目的写回仍会回「身份不符」（mismatch），照实显示，不算清掉。
- 媒体库选择里「其他」视频库不再标成不建议。

## 0.1.0 - 2026-11-05

- 首个版本。在插件页面选一个媒体库和若干成员（含超管 0）：这些成员在这个库里**播放结束后**
  （`playback.stopped` / `playback.completed`），延迟一段时间（默认 45 秒，5–300 可调）再把那一集 / 那部片的
  续播进度清零。
- 只经 `playback.sync.state` 写 `position_ms = 0`，带 `expected_updated_at` 做 compare-and-set；
  冲突时重读一次、仍有进度就重试一次。不动已看、收藏、播放次数、音轨字幕、最近播放时间和播放流水。
- 可选每小时「兜底扫描」（默认开）：扫一遍选中库里选中成员残留的续播进度。
- 默认「只预览」：自动处理只记录会清什么；页面上的「立即清理一次」确认后真的写，不受这个开关影响。
- 没选媒体库或没选成员时什么都不做。
- 清理记录保存清理前的位置，可逐条撤销（之后又播过会冲突，撤销不了）；撤销过、之后没再动的单元，兜底扫描不会再清。
- 插件页面：概览 / 设置 / 清理记录。
