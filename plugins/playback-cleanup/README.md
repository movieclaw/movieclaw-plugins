# 续播进度清理

播放结束后，自动把**选定成员**在**选定媒体库**里的续播进度清掉——下次打开从头播，
首页「继续观看」里也不再挂着。适合给孩子 / 家人用的库、试看片、背景音乐式播放的库。

## 它只清什么

- **只清续播进度**（`position_ms → 0`）。
- **不动**：已看标记、收藏、播放次数、音轨 / 字幕偏好、最近播放时间、
  活动页的播放流水（`playback_log` / 观看记录 / 播放统计）。

## 什么时候清

1. **播放结束后（主路径）**：订阅宿主的 `playback.stopped` / `playback.completed` 事件。
   选中成员在选中库里停止或看完后，等「播放结束后延迟秒数」（默认 **45 秒**，可设 5–300），
   再读一次当前状态：
   - 续播位置已经是 0（看完了 / 别处清过）→ 什么都不做；
   - 还有位置 → 用 `playback.sync.state` 写 `position_ms = 0`，带 `expected_updated_at` 做 compare-and-set；
   - **冲突**（客户端在停止后又补报了一次进度）→ 重读一次，仍有位置就用新版本**重试一次**。

   延迟是为了躲开客户端停止后那最后一次进度上报。同一集的「停止」和「看完」成对到时只清一次。
   插件重启时还没到点的延迟清理会接着排上。
2. **兜底扫描（可选，默认开）**：每小时扫一遍选中库、选中成员残留的续播进度并清掉
   （没有「多少小时前」的过滤：只要还挂着就清）。关掉「兜底扫描」就只靠播放事件。
   宿主「设置 → 定时任务」里叫「续播进度兜底清理」，频率可在那里改。

## 设置（都在插件页面「设置」里）

| 设置 | 默认 | 说明 |
|---|---|---|
| 目标媒体库 | 未选择 | 只能选一个。**不选时插件什么都不做**（事件、定时、手动都不做） |
| 成员 | 不勾 | 多选，含「超管 (0)」。**一个都不勾时插件什么都不做** |
| 播放结束后延迟秒数 | 45 | 5–300 |
| 兜底扫描 | 开 | 每小时一次 |
| 启用 | 开 | 关掉后播放事件和兜底扫描都不做事；手动预览 / 清理仍可用 |
| 只预览（自动处理） | **开** | 播放结束后的清理和兜底扫描只记录会清什么、不写；确认没问题再关 |

页面「概览」里：

- **立即预览**：只列出会清哪些，不写入；
- **立即清理一次**：确认后**真的清**，不受「只预览」开关影响。

宿主的观看同步覆盖电影 / 剧集 / 「其他」库的视频条目。有 TMDB / IMDb 编号的条目写回时带上编号；
两个编号都没有的本地条目只凭条目 id + 类型写回——这需要宿主带 local-null 同步补丁（后续正式版）。
在旧宿主（0.46.0）上：「其他」库的视频看不到；没有编号的电影会显示「身份不符」，清不掉。

## 清理记录与撤销

每次真的清理都会记下清理前的位置和当时的状态版本。「清理记录」里点 **撤销** 会再用
`playback.sync.state` 把 `position_ms` 写回原值。撤销是尽力而为：之后又播过（状态版本变了）就会冲突、撤销不了。
撤销过、之后没再动过的那一集，兜底扫描不会又把它清掉。记录最多保留最近 120 条。

## 需要批准的东西

宿主操作（安装时逐条批准）：

| 操作 | 用途 |
|---|---|
| `members.list` | 设置页列出成员 |
| `library.list` | 设置页列出媒体库 |
| `library.items.list` | 读出选中库里有哪些条目（观看目录没有按库过滤） |
| `playback.sync.catalog` | 读选中成员的续播位置与状态版本 |
| `playback.sync.state` | ⚠ **危险操作**：写回续播位置（只写 `position_ms`） |

**敏感事件**：安装时宿主会请求批准订阅 `playback.stopped`（停止播放）和 `playback.completed`（看完）。
这两个事件涉及「谁在什么时候看了什么」，宿主会单独提示。插件只用它们判断要不要排一次延迟清理，不外传。

不需要网络，不需要任何路径授权。插件网页与接口只有管理员能用。

## 注意

- **双向同步会把进度写回来**：如果装了 Trakt 同步，或 Emby / Jellyfin / Plex 等会双向同步观看进度的插件 / 能力，
  对端仍带着进度时，可能在下一次同步时把续播点写回来。
- 本插件经 `playback.sync.state` 写入，宿主**不会**为这次写入发出 `playback.marked_*` 等事件，
  所以其他插件（包括 Trakt 同步）不会「看到」这次清理。
- 观看目录（`playback.sync.catalog`）没有按库过滤，兜底扫描和手动运行要翻完选中成员的整个目录，
  再在插件里按库内条目筛；库很大、成员很多时一次扫描会多花些时间。播放结束后的清理只定位那一集，不翻全量。
