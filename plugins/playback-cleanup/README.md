# 续播进度清理

播放结束后，自动把**选定成员**在**选定媒体库**里的续播进度清掉——下次打开从头播，
首页「继续观看」里也不再挂着。适合给孩子 / 家人用的库、试看片、背景音乐式播放的库。

## 它只清什么

- **清续播进度**（`position_ms → 0`），宿主支持时同一次写回再带 `dismiss_continue=true`，把这部作品从首页
  「接下来继续」（含 App「本设备」条）拿掉。
  - 只清进度不够：没看完（`played=false`）的片宿主仍算「能接着看」，卡片照样在。
  - 隐藏是**作品级**的：不当成已看、不跳到下一集；再次播放后宿主自动取消隐藏，卡片回来。
  - 剧集只对**当前集**（这部剧里 `last_played_at` 最近的那一集，与宿主「接下来继续」取锚点同一口径）带
    `dismiss_continue=true`；较旧的集只清进度、不带这个字段（宿主会拒绝落在非当前集上的隐藏，整条回冲突）。
    旧集进度已是 0、作品已隐藏时不再处理。平局时宿主按状态行 id 取，catalog 不给 id，插件取季 / 集号大的那集。
  - 写回前别的设备又播了别的集（当前集变了）：宿主回冲突，插件重读这部剧、按最新的当前集重算再试一次；
    仍冲突就记为冲突并说明原因，不会当成已隐藏。需要带 MovieClaw#1246 的宿主。
  - **需要新版宿主**（catalog 行带 `continue_dismissed`）。旧宿主（包括现有的 0.49.1）上插件只清进度、
    不发送这个字段（否则整批 422），并在结果和清理记录里提示「宿主不支持隐藏『接下来继续』」——
    **单装插件 0.1.3 不能让 0.49.1 的卡片消失**。
- **不动**：已看标记、收藏、播放次数、音轨 / 字幕偏好、最近播放时间、
  活动页的播放流水（`playback_log` / 观看记录 / 播放统计）。

## 什么时候清

1. **播放结束后（主路径）**：订阅宿主的 `playback.stopped` / `playback.completed` 事件。
   选中成员在选中库里停止或看完后，等「播放结束后延迟秒数」（默认 **45 秒**，可设 5–300），
   再读一次当前状态：
   - 续播位置已经是 0（看完了 / 别处清过）→ 什么都不做；新宿主上例外：作品当前集没看完、播过、
     作品还没隐藏的（比如 0.1.2 只清了进度的）会补上隐藏；
   - 还有位置 → 用 `playback.sync.state` 写 `position_ms = 0`，带 `expected_updated_at` 做 compare-and-set；
   - **冲突**（客户端在停止后又补报了一次进度）→ 重读一次，仍有位置就用新版本**重试一次**。

   延迟是为了躲开客户端停止后那最后一次进度上报。同一集的「停止」和「看完」成对到时只清一次。
   插件重启时还没到点的延迟清理会接着排上。
2. **兜底扫描（可选，默认开）**：每小时扫一遍选中库、选中成员残留的续播进度并清掉
   （没有「多少小时前」的过滤：只要还挂着就清）。关掉「兜底扫描」就只靠播放事件。
   宿主「设置 → 定时任务」里叫「续播进度兜底清理」，频率可在那里改。

## 设置（都在插件页面「设置」里）

| 设置 | 默认 | 说明 |
|---|---|---|
| 目标媒体库 | 未选择 | 只能选一个。**不选时插件什么都不做**（事件、定时、手动都不做） |
| 成员 | 不勾 | 多选，含「超管 (0)」。**一个都不勾时插件什么都不做** |
| 播放结束后延迟秒数 | 45 | 5–300 |
| 兜底扫描 | 开 | 每小时一次 |
| 启用 | 开 | 关掉后播放事件和兜底扫描都不做事；手动预览 / 清理仍可用 |
| 只预览（自动处理） | **开** | 播放结束后的清理和兜底扫描只记录会清什么、不写；确认没问题再关 |

页面「概览」里：

- **立即预览**：只列出会清哪些，不写入；
- **立即清理一次**：确认后**真的清**，不受「只预览」开关影响。

宿主的观看同步覆盖电影 / 剧集 / 「其他」库的视频条目。有 TMDB / IMDb 编号的条目写回时带上吻合的编号；
两个编号都没有的本地条目写回时带上读观看目录那一刻宿主下发的**身份令牌**（`media.identity`，即条目的
`external_id`）——需要 MovieClaw v0.49.0 及以上（#1203）。令牌防的是「删掉 A、新建的 B 复用了同一个数字 id」：
拿着 A 的令牌写回会被宿主拒为「身份不符」，不会清到 B 上。冲突重读后如果条目身份变了，也不会改用新身份再写。

在旧宿主（v0.46–0.48）上：观看目录不下发令牌，插件就不发这个字段（旧宿主多收一个字段会整批拒绝），
请求与 0.1.1 一样；「其他」库的视频看不到（目录不认 `kinds`，自动退回只看电影 / 剧集）；
没有编号的电影会显示「身份不符」，照实显示、不算清掉。

## 清理记录与撤销

每次真的清理都会记下清理前的位置和当时的状态版本。「清理记录」里点 **撤销** 会再用
`playback.sync.state` 把 `position_ms` 写回原值；那次一起隐藏过的，`dismiss_continue` 也写回清理前的真实值
（0.1.2 及以前的记录不带这个字段）。撤销是尽力而为：之后又播过（状态版本变了）就会冲突、撤销不了。
撤销过、之后没再动过的那一集，兜底扫描不会又把它清掉。记录最多保留最近 120 条。

本地条目（没有外部编号）的记录会存下当时用的身份令牌，撤销只用这个令牌，不会再去读观看目录拿「现在的」令牌
——那个 id 可能已经是另一部片了，此时宿主回「身份不符」，撤销不了。0.1.1 留下的本地条目记录没有令牌，
显示「无法安全撤销」，不会发任何请求；有外部编号的旧记录照常可撤销。

## 需要批准的东西

宿主操作（安装时逐条批准）：

| 操作 | 用途 |
|---|---|
| `members.list` | 设置页列出成员 |
| `library.list` | 设置页列出媒体库 |
| `library.items.list` | 读出选中库里有哪些条目（观看目录没有按库过滤） |
| `playback.sync.catalog` | 读选中成员的续播位置与状态版本 |
| `playback.sync.state` | ⚠ **危险操作**：写回续播位置（只写 `position_ms`，新宿主上加 `dismiss_continue`） |

**敏感事件**：安装时宿主会请求批准订阅 `playback.stopped`（停止播放）和 `playback.completed`（看完）。
这两个事件涉及「谁在什么时候看了什么」，宿主会单独提示。插件只用它们判断要不要排一次延迟清理，不外传。

不需要网络，不需要任何路径授权。插件网页与接口只有管理员能用。

## 注意

- **双向同步会把进度写回来**：如果装了 Trakt 同步，或 Emby / Jellyfin / Plex 等会双向同步观看进度的插件 / 能力，
  对端仍带着进度时，可能在下一次同步时把续播点写回来。
- 本插件经 `playback.sync.state` 写入，宿主**不会**为这次写入发出 `playback.marked_*` 等事件，
  所以其他插件（包括 Trakt 同步）不会「看到」这次清理。
- 观看目录（`playback.sync.catalog`）没有按库过滤，兜底扫描和手动运行要翻完选中成员的整个目录，
  再在插件里按库内条目筛；库很大、成员很多时一次扫描会多花些时间。播放结束后的清理只定位那一集，不翻全量。
