# 更新记录

## 1.1.0 - 2026-11-13

在 1.0.0 的三个引擎上加「转完能收尾、删片能联动、跑完能被别的功能看见」。

转种

- 校验编排升级：加种后持续盯目标下载器，以目标自己的判断为准（本地报错 / 进度 100% /
  超时）。本地报错且重下就能恢复的任务自动清掉，不再让空壳任务堆在清单里；
  「分片损坏」这类删了就找不回来的只告警，不代劳。
- 扫描改为直连下载器取「已完成」清单：内核的任务视图只显示未完成任务与入库收尾中的任务，
  已完成的外部种会被隐藏，以前按它扫会永远扫不到东西。
- 站点标签（MP 风格）：按种子文件里的 tracker 域名补一条「站点/名字」，配合转种 / 辅种标签，
  一眼分清主种、辅种和来源站。
- 删源安全线：MovieClaw 投递的种（订阅 / 手动下载）默认跳过，避免删掉后订阅判定缺资源又重下。

辅种

- IYUU 接口修复：sid_sha1 先报后用（报「站点哈希值」错时自动重报）、限流退避重试、
  时间戳随重试刷新、info_hash 分批（每批 200）。
- 取种链接三级策略：按发布名在目标站搜索精确命中 → 名称模糊命中 → IYUU 模板链接回填
  站点凭据兜底（模板里的 `{passkey}` 保留到凭据库回填这一步，不再提前剥掉）。
- 台账：成功辅过的按源种分组，逐条可删（顺带从下载器移除该任务，不会再自动加回）；
  已在做种但台账没有的历史辅种自动补录。
- 站点冷却：单站连续失败自动冷却（超时 1 小时、要凭据 / 种子已删 24 小时），不拖住整轮。

保活守护

- 判死口径收紧：全部真实 tracker 都报 `not registered` / `torrent banned` 才算站点已删种；
  TR 本地 `No data found` 且校验未过才算数据丢失；「分片损坏」只告警、建议重新校验。
- 主种空壳处理：MovieClaw 主种的数据已不在原位时，先用内核删种预演判断——会被订阅
  重下的一律保留，只是空壳的才清掉。
- 保护标签（默认「留」「保留」）与 MovieClaw 主种永不碰；只删任务不删文件；
  默认「只报告不删除」。

删片联动（新）

- 监听媒体库的删片与清空回收站（可靠事件，按投递 id 幂等）：删片后立刻把对应的下载任务
  从下载器里移除，不用等守护下一轮。
- 按媒体库文件 id 反查来源任务，三道安全线任一命中就保留：下载器配置已删除、
  这个种还供着库里别的文件、投递时有 H&R 考核风险；主种额外过一遍内核删种预演。
- 两个开关：删片后自动停种（默认开）；停种时同时删数据文件（默认关，只留孤立文件）。

与系统其它能力打通（新）

- 三个插件事件：转种完成 / 辅种完成 / 保活守护完成，Webhook 和别的插件都能订阅。
- 两条通知模板（转种完成、守护清理），默认关，想推到手机 / IM 去「设置 → 通知」打开。
- 健康上报：常驻任务连续失败会显示成插件异常，恢复后自动转好，不用盯着日志找。

界面

- 左侧栏「保种管家」一页三标签：概览（转种 / 辅种 / 守护三张卡 + 配置自检 + 最近报告）、
  待清理（完整候选表，比报告里的明细全）、运行日志（只显示本插件的日志，按级别过滤、
  可清空、跨重启保留）。
- PC 端三张卡同一行、高度对齐；手机端卡片式重排；配色跟随主题变量；按钮与文字不再留大空隙。
- 新增 mclaw 命令：`status`、`run`、`logs`、`sweep-candidates`、`transfer-scan`、
  `verify-check`、`reseed-ledger`、`reseed-ledger-delete`、`cooldown-clear`、
  `credentials`、`credentials-refresh`、`sites`。

权限与契约

- 新增宿主操作：`dl.file-sources.list`（删片停种反查来源任务）、`site.proxy.request`
  （危险：借宿主登录态打开站点详情页，解析真实取种链接，凭据不出宿主）。
- 新增契约：`download.completed`、`library.ingest.completed`、`library.file.deleted`、
  `library.file.purged`、`kernel/durable-events`、`plugin-events`、`plugin-health`。

## 1.0.0 - 2026-10-23

首个发布版本：转种、辅种、保活守护三个引擎，共享同一套「判重 → 路径换算 → 加种 → 校验编排 → 删源 → 报告」流程。

转种（本地搬运）

- 源侧读磁盘种子文件（qB 的 BT_backup、TR 的 torrents 目录，`<info_hash>.torrent`），
  任意版本的 qBittorrent / Transmission 都能当源；qB ≥ 4.5 磁盘文件缺失时用 WebUI 导出兜底。
- 磁力添加、缺 announce 的种子：用源下载器里的 tracker 补齐后再加种。
- 目标路径换算直接用内核里两台下载器已配的路径映射，不用重复填一遍。
- 校验编排：不跳校验时加入后触发校验，后台 watcher 每分钟看进度，完成即恢复做种；
  目标 qB + 跳过校验时直接开始做种。
- 删源（默认关）走内核 `dl.torrent.delete`：过 H&R 保护、订阅状态正确联动，只删任务不删文件；
  目标已有同种时可顺手清源（也默认关）。
- MP 风格站点标签：按种子 tracker 域名识别来源站点，补一条「站点/昵称」标签。

辅种（IYUU 跨站补种）

- IYUU 匹配接口完整对接：sid_sha1 先报后用（报「站点哈希值」错时自动重报再试）、
  限流退避重试、时间戳随重试刷新、info_hash 分批（每批 200）。
- 站点映射：slug 直配 → 域名兜底；站点昵称从 IYUU 目录运行时拉取。
- 取种链接三级策略：优先按发布名在目标站搜索真实链接（id 精确命中 → 名称模糊命中）；
  搜不到再回填 IYUU 模板链接——回填用浏览/搜索时学到的站点凭据（passkey 等），
  让原本必死的兜底链接可用。
- 沿用原种保存路径（IYUU v2.18 口径），辅种与原种同目录，找得齐数据。
- 成功缓存 + 台账：辅过的不再重复提交；历史辅种自动补录；台账逐条可删（顺带删下载器任务）。
- 站点冷却：单站取种连续失败自动冷却（超时 1 小时、要求凭据/已删种 24 小时），不让一个慢站拖住整轮。
- 每轮上限与 10 分钟时间预算，防止一次把下载器塞爆。

保活守护（智能清理）

- 「站点已删种」：全部真实 tracker 都报 not registered / torrent banned 才判死
  （qB 排除 DHT/PeX/LSD 伪条目与「私有 torrent」提示行；有一个 tracker 活着就是活种）。
- 「数据丢失」：TR 本地错误 No data found 且校验未过；校验完好的不动（可能只是路径变了）。
- MovieClaw 主种（movieclaw-* 标签）与保护标签的种永不碰；只删任务不删文件；
  默认「只报告不删除」，跑几轮看过报告再放开。

体验

- 左侧栏「保种管家」：概览（配置自检 + 三份报告）、待清理（完整候选表格）、运行日志
  （跨重启保留，可清空）。
- 三个定时任务（转种 6h / 辅种 24h / 守护 12h）在「设置 → 定时任务」调周期；
  配置不齐自动跳过并记日志，绝不半配置硬跑。
- 网络走 MovieClaw 的代理设置；凭据（WebUI 密码、IYUU 令牌）全部加密存储、界面不回显。
