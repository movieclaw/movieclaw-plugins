# 演员头像补全（`actor-avatar`）

用 [gfriends](https://github.com/gfriends/gfriends) 头像库，给**本地视频库**（在插件页面勾选；没选库时插件什么都不做）条目里没有头像的演员补头像。

只做一件事：往条目视频旁的 `<番号>.nfo` 写 `<actor><thumb>`，再触发一次「重新读取 NFO」。
不碰视频、不改主程序数据库、不处理 TMDB 刮削的电影/剧集库。

> ⚠️ **当前 MovieClaw（0.46 / 0.47.1）本地库有一个缺口**：扫描入库时 NFO 里的演员头像能显示，
> 但**刷新元数据（重读 NFO）时**头像存成了 `thumb`，详情页却读 `nfo_thumb`，于是刷新后头像不显示——
> 连 NFO 里原本就有、本来显示着的第三方头像也会在刷新后消失。插件写完必须触发刷新，所以：
>
> - 每次写入都先拿第一部「探路」：刷新后复核详情，头像没出来就**立即停手**（只改了这一部），面板提示，
>   入库触发的写入暂停；每日任务和「立即写入一轮」会再探一次。
> - 主程序修复（`services/library/local_identity.py` 演员条目加一行 `"nfo_thumb": actor.thumb or None`）后，
>   下一次探路成功即自动接着写，并把之前写了没显示的条目重新刷新一次。插件无需改动。

## 它怎么工作

1. **触发**：定时任务（默认每天 04:30，可在「设置 → 定时任务」改）、新片入库事件、面板手动运行。
2. **选库**：在侧栏「演员头像」页面的「目标媒体库」里直接勾选——列出服务器上全部媒体库（名称、类型、来源），
   只有「其他视频（video）+ 本地目录（local）」的库能勾，其余灰掉并注明原因；按库 id 保存（改库名不受影响）。
   没勾选过时不处理任何库（定时任务、入库、手动运行都直接跳过，页面提示先去勾选）。0.1.x 设置里手填的 `libraries`（库名或数字）首次运行时自动解析成勾选结果，只迁移一次。
   （主程序的插件设置表单只支持静态选项，没法列出动态的库列表，所以选择器放在插件页面里。）
3. **索引**：下载 gfriends 的 `Filetree.json`（约 6.5 MB，gzip 传输约 1 MB），带 `If-None-Match` 条件请求，
   以 gzip 存进插件私有目录；源站失败时继续用旧索引。
4. **匹配**（只有确认档才写）：
   - 别名（用户在「待确认」里确认过的）→ 原名 → 去空白/全半角/大小写/点号、展开叠字符号（`野野浦暖` ↔ `野々浦暖`）
     → 简繁日字形折叠 → 括号别名（`美月恋(美月レイア)`）→ **中文译名表**（`凉森玲梦` → `涼森れむ`，见下）；
   - 同名多张时按 gfriends 约定取质量最高的公司（Filetree 里靠后的）；默认优先 AI-Fix 修复版。
   - **推断档**：一部片只剩一个演员查不到时，用片名最后两个词去索引里找，候选进「待确认」，**不写**。
5. **跳过**：档案里已有头像的演员、NFO 里已有别人写的头像的演员一律不动。
6. **写入**：
   - 已有 NFO：只加/替换本插件拥有的 `<thumb>`；写前做不变式检查（去掉本插件的 thumb 后整棵树必须与原文一致），
     根元素前的声明和注释原样保留；只接受 UTF-8 的 NFO；
   - 没有 NFO：新建 `<番号>.nfo`，只含当前 `<title>` 和档案里的**全部**演员（含角色）——主程序重读 NFO 时演员表是整表替换的，
     少写一个就会丢一个；
   - 原文备份到插件私有目录（不往媒体目录丢 `.bak`），原子写（临时文件 + rename）。
7. **刷新与复核**：触发 `library.items.refresh-metadata`，等刷新任务结束后看详情的演员头像是否到位，结果写进报告。

## 中文译名表

刮削器常把演员名写成中文译名（`凉森玲梦`、`八挂海`），gfriends 只有日文名。插件运行时下载
[MDCx](https://github.com/sqzw-x/mdcx) 的 `resources/mapping_table/mapping_actor.xml`（约 860 KB，5000+ 位演员的简体/繁体/日文名与别名），
经 jsDelivr（头像源选 GitHub 时走 raw.githubusercontent.com）条件请求（ETag），解析成「折叠后的名字 → 日文名」表，
以 gzip 存进插件私有目录，刷新间隔同索引；源站失败时用旧表，从没下到过就只按原名匹配并在报告里注明。

- 整条标 `【誤認注意】` 的不用，只是某个别名带 `【誤認注意】` 后缀的只丢那个别名；`【同名異人】` 只用该条的简/繁/日文名，不用别名串；一个名字对应多个日文名的直接丢掉；
  少于两个字的名字不用。查表结果仍要在头像库里有同名头像才算命中，只作为最后一步（不覆盖直接命中）。
- **许可**：MDCx 以 GPL-3.0 发布并附加「仅限学习与技术交流、不得商用」条款，仓库已于 2026-09 归档。为不把 GPL 数据并入本插件（MIT），
  插件包里**不附带**这份表，只在你的服务器上按需下载使用；不需要可在设置里关掉「中文译名表」。

## 头像地址

| 写法 | NFO 里的地址 | 适用 |
|---|---|---|
| 直接写镜像地址（默认） | `https://cdn.jsdelivr.net/gh/gfriends/gfriends@master/Content/<公司>/<文件>` | 网页端经主程序 `/images/proxy` 回源并缓存，最省事 |
| 插件下载并托管 | `<外部地址>/api/v1/plugins/actor-avatar/avatar/<sha1>.jpg?sig=…`（不过期签名） | 需要外部访问地址是**公网域名 + 80/443**；主程序图片代理拒绝 IP 直连和非标准端口 |

头像源可选 jsDelivr（默认）、GitHub 原站、自定义镜像（指向仓库根目录）。

| 字段 | 标题 | 默认 |
|---|---|---|
| `enabled` | 启用插件 | 开 |
| `dry_run` | 只预览不写入 | **开** |
| `name_table` | 中文译名表（MDCx） | 开 |
| `mirror` / `custom_base_url` | 头像源 / 自定义源地址 | jsDelivr 镜像 |
| `ai_fix` | 优先 AI 修复版 | 开 |
| `thumb_mode` / `public_base_url` | 头像地址写法 / 外部访问地址 | 直接写镜像地址 |
| `infer_from_title` | 从片名推断候选 | 开 |
| `process_arrivals` | 新片入库时处理 | 开 |
| `max_items_per_run` | 每轮最多处理（1–5000） | 200（下一轮从断点续） |
| `request_interval_ms` | 请求间隔（毫秒） | 800 |
| `filetree_ttl_hours` | 索引 / 译名表刷新间隔（小时） | 24 |
| `skip_junk_names` | 过滤刮削器写进来的描述性名字 | 开 |
| `ai_suggest_on_run` | 每轮运行后用 AI 推荐别名（每轮最多 5 位） | **关** |
| `ai_daily_limit` | AI 推荐每日上限（位演员，0 = 不用 AI） | 20 |
| `search_enabled` | 按番号搜索补头像（结果只进待确认） | 开 |
| `search_avwiki` / `search_javdb` / `search_dmm` | 来源开关 | 都开 |
| `dmm_api_id` / `dmm_affiliate_id` | DMM 官方接口（密码字段，不回显；两个都填才用） | 空 |
| `search_per_run` | 每轮最多搜索（1–30 位） | 5 |
| `search_interval_s` | 同站请求间隔（2–60 秒） | 5 |
| `search_cooldown_days` | 没搜到后冷却（1–365 天） | 30 |
| `search_auto_write` | 交叉验证通过自动写入（只限同名） | **关** |

目标媒体库不在设置表单里，在插件页面勾选（见上）。

**在插件页面里改设置（0.4.0）**：插件页面的「设置」页签能改上表全部字段（分「基本 / 头像来源 / 写入 / 搜索补头像 / AI / 高级」六组，
带中文说明与校验），加上目标媒体库勾选。页面以当前管理员身份调主程序的插件通用设置接口
`GET` / `PUT /api/v1/app/plugins/actor-avatar/settings`（与「设置 → 插件 → 演员头像补全」同一份存储；
主程序用本插件的配置模型校验，保存后重启插件，起不来会自动恢复原设置），所以两边始终一致。
页面不能授予权限，也不能解锁自动写入（解锁只有「概览」里的「立即写入一轮」）；关掉「只预览」与在主程序设置页关掉效果相同。

**只预览与自动写入**：`dry_run` 默认开。关掉之后，入库事件和定时任务**也不会立刻开始写**——要先在面板点一次
「立即写入一轮」（手动写入一次 = 解锁），之后自动运行才会真正写入；面板「停止自动写入」随时回到只预览。
没解锁时自动运行照常出预览，报告里会注明。这样即使设置表单里误关了只预览，也不会在无人看着时改 NFO。

## 手动处理与 AI 推荐（0.3）

面板「没配上的演员」列出最近几轮里查不到头像的演员（每人带几部片的番号 / 片名），每人可以：

- **对上**：输入框自动补全，候选来自 gfriends 名字（前缀 / 子串）和 MDCx 译名表（译名 → 日文名，日文名必须在 gfriends 里）。
  只能存成 gfriends 里真有的名字。
- **上传头像**：页面先把图缩到 600px 以内转 JPEG 再传；插件只收 JPG / PNG / WebP、≤ 5 MB，存在插件私有目录，
  以签名地址 `…/avatar/<sha1>.<ext>`（公开区）写进 NFO，所以**需要外部访问地址**（设置 → 应用，或本插件设置）；
  没有时保存照常，但写入会被拦下并提示。
- **AI 推荐别名**：见下。

手动设置**优先于一切自动匹配**（连本来能精确命中的也会被覆盖），保存后自动重跑相关条目。这类重跑和自动运行一样受
「只预览 / 自动写入解锁」约束：没解锁时只出预览、不会顺带解锁。写入照常进台账、可撤销；删除手动设置不动已写的 NFO。

**刮削垃圾名**：素人片刮削常把介绍文字当演员名（`京香 大学生モデル`、`かすみ 28歳 …`、`あおいさん`），
这些串不拿去匹配、不进待确认、不让 AI 猜，在面板折叠区单独列出（仍可手动对上 / 上传）。

**AI 推荐别名**（用 MovieClaw 内置的 AI 助手，插件 SDK 的 `AGENT` 服务，权限 `agent:none`）：

- 只发「演员名 + 最多 3 部片的番号 / 片名」，`tools="none"`（不给工具），要它回 JSON 名字数组。
- 每个名字再走一遍普通匹配，**gfriends 里查得到才收下**，而且**只进「待确认」**（标「AI 推荐」），不自动写入。
- 页面上按人点；设置里可开「每轮运行后自动推荐」（默认关，每轮最多 5 位，跳过垃圾名 / 已手动设置 / 待确认里的 / 30 天内问过的）。
- 护栏：每日上限（默认 20 次）、串行且两次之间至少隔 3 秒、单轮 120 秒超时；主机侧每个插件最多同时 2 轮。
  token 用量（输入 / 输出 / 合计，今日与累计）记在插件数据里、面板可见；会话问完即删。
- 需要：MovieClaw ≥ 0.40（插件 AI 接口）、**安装 / 升级时批准 `agent:none`**（主程序会标成危险权限：以管理员身份运行、按模型用量计费），
  并且主程序配置了可用模型；否则按钮灰掉 / 报「没配置模型」，其余功能不受影响。

## 按番号搜索补头像（0.5）

gfriends 里配不上的演员，用她片子的番号（NFO `<num>`、标题或文件名里的 `ABC-123`）去查演员表认人、取头像：

| 来源 | 查什么 | 给什么 |
| --- | --- | --- |
| av-wiki | `https://av-wiki.net/<番号>/` 的「AV女優名」 | 认人；只有一人且不同名时给「正名」（别名），正名先查 gfriends |
| javdb | 搜索番号（完全相等）→ 作品页女演员 | 演员头像 `c0.jdbstatic.com/avatars/…`（403 = 没头像） |
| DMM | 按 av-wiki 罗马字 slug 猜 `pics.dmm.co.jp/mono/actjpgs/…`；或官方接口（可选） | 猜的一律标「猜测」；官方接口按番号认人 |

- 演员必须出现在**该番号**的演员表里才算：完全同名 =「同名」，av-wiki 单人不同名 =「别名」，其它判定不了就看下一个来源。
- 只认真图片：200、`image/*`、不跟随跳转、不是 DMM 占位图；确认后写入前还会再验证一次。
- 被拦（403 / 429 / 挑战页 / 连不上）的来源本轮暂停，不算没搜到。同站请求串行、默认间隔 5 秒。
- 结果**只进「待确认」**；确认后 NFO 里直接写来源图片地址（别名对上 gfriends 的记成普通别名）。写入照常受只预览 / 解锁约束、可撤销。
- 自动：定时任务 / 新片入库那一轮之后，每轮最多 5 位，没搜到的 30 天内不再自动搜；手动：「没配上的演员」里点「搜索头像」（无视冷却）。
- 「交叉验证通过自动写入」默认关；开了也只自动写「同名 + av-wiki / javdb / DMM 官方接口」的结果，别名和猜测永远要人确认。
- DMM 官方接口（`api_id` + `affiliate_id`，免费注册）是可选的，存为密码字段：不回显、不进报告 / 事件 / 日志。
- **条款风险**：这些站点并不提供这种用途，请**仅限个人自用、低频**使用。不需要新权限（沿用 `network = true`）。

## 面板

侧栏「演员头像」，0.4.0 起分五个页签，每页只放一类内容（长列表都带搜索与分页）：

- **概览**：当前模式（只预览 / 自动运行仍只预览 / 自动写入已开启）、立即预览 / 立即写入一轮 / 停止自动写入、
  四个数字（已写入条目 / 头像、待确认、没配上）、最近一轮摘要；只显示需要处理的提醒（没选库、主程序不显示头像、
  托管模式且外部地址不可用、索引更新失败）。
- **待确认**：推断 / AI 推荐 / 按番号搜索来的候选头像（经主程序图片代理显示），「就是她」/「都不是」。
- **没配上的演员**：每人点「处理」展开：对上 gfriends 名字、上传头像、AI 推荐别名；刮削垃圾名折叠在下面；「已手动设置」单独一栏。
  外部访问地址不可用时，只在这里和设置里提示。
- **写入记录**：已写入（单条撤销、全部撤销）、处理明细（按状态筛选）、运行记录。
- **设置**：见上。托管模式 / 上传头像的地址提醒显示在「头像地址写法」「外部访问地址」旁边，镜像模式且没上传过头像时不提示。

## 撤销

台账记录每部片：NFO 路径、是否本插件新建、本插件写的 `演员 → thumb`。撤销只删除值完全相同的 `<thumb>`（用户改过的不碰），
然后刷新；本插件新建且用户没改过的 NFO，在刷新完成后整份删除。

## 已知限制

- 主程序缺口（见顶部）：修复前头像不显示；本地条目没有人物表记录，Jellyfin 兼容层的 People 也不会有头像。
- 新建 NFO 后条目的识别来源会变成 NFO；撤销删除 NFO 后不会自动改回（不影响片名和其他字段）。
- 只处理 UTF-8 NFO；原盘（ISO/BDMV）没有 sidecar NFO，跳过。
- gfriends 头像库按其仓库条款仅限非商业使用；MDCx 译名表同样限非商业（见上）。
- 译名表覆盖的是 MDCx 收录的演员；头像库里没有的人（例如 `黒木奈美`）查到日文名也补不上。
