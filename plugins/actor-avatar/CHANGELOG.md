# 演员头像补全

## 0.5.1 - 2026-11-05

- **去掉默认目标库**：以前没在插件页面勾选过、也没有 0.1.x 旧设置 `libraries` 时，会按库名「小姐姐」找库；现在不再有任何默认库。
  没选库时定时任务、新片入库、手动运行、按番号搜索和 AI 推荐都不做任何事（不读条目、不写文件、不记运行记录），
  只记一行日志；运行结果状态为 `no_selection`，报告里 `settings.library_source` 为 `none`，插件页面「概览」顶部提示去「设置」勾选目标媒体库。
- **已有的勾选不受影响**：在插件页面保存过的勾选照旧生效，0.1.x `libraries` 设置的一次性迁移也和以前一样。
  从没保存过勾选的安装（以前靠默认库名工作的）升级后需要到插件页面勾选一次目标媒体库并保存。

## 0.5.0 - 2026-11-04

- **按番号搜索补头像**（只针对 gfriends 里配不上的演员）：用片子的番号（NFO `<num>` → 标题 → 文件名，规范成 `ABC-123`；
  拿不到番号就跳过）依次查 **av-wiki → javdb → DMM**，每个来源可单独开关。
  - 认人规则：演员必须出现在**该番号**的演员表里。完全同名 = 「同名」；av-wiki 演员表只有一人且名字不同 = 「别名」
    （正名先查 gfriends，有就用 gfriends 的图；没有就带着正名继续查后面的来源）；多人无同名 / 空表 = 这个来源判定不了。
  - javdb：搜索结果番号必须完全相等，再取作品页女演员与演员头像（没头像返回 403 = 没图）。
  - DMM：没配官方接口时按 av-wiki 的罗马字 slug 猜头像地址（原样 / 训令式 / 带 2），会认错同名的人，所以一律标「猜测」；
    可选配置 DMM 官方接口（api_id + affiliate_id，两个都填才用），按番号查演员表，同名才用。
  - 只接受真实图片：HTTP 200、`image/*`、不跟随跳转（3xx = 没图）、大小合理、不是 DMM 的 now_printing 占位图。
  - 反爬（403 / 429 / 挑战页 / 连不上）：该来源本轮暂停并记一条事件，不算演员没搜到、不进冷却。
  - av-wiki 偶尔回 200 的加载页 / 半截页：页面既不含该番号也没有「AV女優名」时，隔一个请求间隔重试 1 次，仍不完整就按被拦处理（本轮暂停 av-wiki、不进冷却），
    不会误当成「没演员表」；页面含该番号但没有演员链接仍算没演员表。标题为 `Loader` 的页面也识别为挑战页。
  - 同一站点串行，相邻请求至少隔「搜索请求间隔」（默认 5 秒），带浏览器 UA。
- **结果一律进「待确认」**：显示来源图片缩略图、来源（可新标签打开来源页面）、番号、匹配方式（同名 / 别名 / 猜测）、演员表摘录（最多 6 人）。
  确认后：搜索来的图片地址直接写进 NFO `<thumb>`（和镜像地址写法一样），写之前再验证一次是 200 的真图；
  经别名对上 gfriends 的，按普通别名记住（以后同名演员直接命中）。照常受「只预览 / 写入解锁」约束、进写入记录、可撤销。
- **「交叉验证通过自动写入」默认关**：开了也只有自动轮次里「同名」且来源是 av-wiki / javdb / DMM 官方接口的结果才直接写
  （还要关掉只预览并已解锁写入）；别名和猜测永远只进待确认；手动点的搜索也只进待确认。
- 触发：只在定时任务 / 新片入库那一轮跑完后，给「没配上的演员」搜，每轮最多「每轮最多搜索」位（默认 5）；
  没搜到的演员「冷却」天数内（默认 30）自动轮次不再搜。「没配上的演员」每人加「搜索头像」按钮（只搜这一位、无视冷却，
  后台任务 + 页面轮询，只锁这一行的按钮，结果留在行内）。确认、预览、手动对上 / 上传、AI 推荐之后都**不会**顺带搜索。
- 设置新增分组「搜索补头像」：`search_enabled`、`search_avwiki` / `search_javdb` / `search_dmm`、`dmm_api_id` / `dmm_affiliate_id`
  （密码字段：主程序不回显，页面只显示「已设置 / 未设置」，留空不改；报告、事件、日志里不出现）、`search_per_run`（1–30）、
  `search_interval_s`（2–60 秒）、`search_cooldown_days`（1–365）、`search_auto_write`。
- 新增路由：`POST /avatar-search`（`{actor}`，排后台任务）、`GET /avatar-search/status?actor=`；新增后台任务 `actor-avatar:search`。
  概览「最近一轮」显示搜索小结（搜了几位、候选几个、哪个来源被拦）。
- **没有新增权限**：仍是原来的 `network = true`（主程序网络出口，跟随「设置 → 网络」的代理）。
- 条款风险：av-wiki / javdb / DMM 都不是为这种用途提供的，**仅限个人自用、低频访问**；默认每轮最多 5 位、同站间隔 5 秒，请不要调得太激进。

## 0.4.0 - 2026-11-04

- 插件页面重新设计：拆成「概览 / 待确认 / 没配上的演员 / 写入记录 / 设置」五个页签，每页内容少；长列表（待确认、没配上、
  非艺名、手动设置、已写入、处理明细）都有搜索与分页；没配上的演员点「处理」才展开手动对上 / 上传 / AI 推荐。
- **设置搬进插件页面**：全部设置项分组（基本 / 头像来源 / 写入 / AI / 高级）、中文名称与简短说明、页面内校验（范围、地址格式、
  自定义源必填），改动有「已改」标记与底部保存条；目标媒体库勾选也在这里。走主程序插件通用设置接口
  （`/api/v1/app/plugins/actor-avatar/settings`，MovieClaw 0.46 起已有），与主程序设置页同一份数据，保存后主程序校验并重启插件。
- 「外部访问地址带非标准端口」等提醒不再是页面顶部横幅：只在设置里「头像地址写法 / 外部访问地址」旁和上传头像处显示；
  镜像模式下只有用过上传头像才提示。概览只在托管模式下提醒。
- 页面不能授予权限、不能解锁自动写入（仍只有手动「立即写入一轮」能解锁）；没有新增权限。
- 出错提示一律中文：主程序 / 插件 / 浏览器的英文兜底说明换成按状态的中文说明；字段校验红字随输入实时消失；
  保存时目标库已存、其他设置失败会如实说明；操作进行中重画出来的按钮也保持禁用；提示条不再盖住保存条。
- 代码按仓库 ruff 配置整理（行宽、import 排序、测试里用 with 打开文件），行为不变。
- `/report` 增加 `link`（地址提醒、是否托管、是否有上传头像）与 `unmatched`（没配上 / 非艺名人数）。

## 0.3.0 - 2026-11-04

- 面板新增「没配上的演员」：最近几轮查不到的演员（带番号 / 片名），可手动**对上** gfriends 名字（自动补全：gfriends + MDCx 译名表）
  或**上传头像**（JPG/PNG/WebP ≤ 5 MB，存插件私有目录，以签名地址写进 NFO，需要外部访问地址）。手动设置优先于自动匹配，
  进台账、可撤销；保存后重跑相关条目。
- 「确认」与手动设置之后的重跑不再「解锁」自动写入：没解锁时只预览（与入库 / 定时任务同一道闸）。
- 刮削垃圾名（`京香 大学生モデル`、`… 28歳 …`、`あおいさん` 等）不拿去匹配，单独列出（设置 `skip_junk_names`，默认开）。
- **AI 推荐别名**：用 MovieClaw 内置 AI 助手（权限 `agent:none`，无工具）给配不上的演员推荐别名；候选必须在 gfriends 查得到，
  只进「待确认」不自动写。按人点，或开 `ai_suggest_on_run`（默认关，每轮最多 5 位）；每日上限 `ai_daily_limit`（默认 20），
  串行 + 间隔、单轮超时、30 天内不重复问；token 用量面板可见。**升级需要重新批准权限（新增 `agent:none`）。**
- 公开区头像路由不再只在托管模式挂载（手动上传也要用）。

## 0.2.2 - 2026-11-04

- 译名表缓存记下解析规则版本；规则变了（如 0.2.1 的修正）时旧缓存作废，即使源文件 ETag 没变也整份重下重解析。

## 0.2.1 - 2026-11-04

- 修正译名表解析：MDCx 里 `【誤認注意】` 多数是挂在某个别名后面的后缀（如 `まひる【誤認注意】`），
  0.2.0 把这类条目整条丢掉了（约 440 条，例如「大槻响 → 大槻ひびき」）；现在只丢带标记的那个别名。
  表键 9531 → 10931；NAS「小姐姐」库全库试算 690 → 721 / 789 位演员可匹配。

## 0.2.0 - 2026-11-04

- 目标媒体库改为在插件页面直接勾选：列出服务器上的全部库，只有本地视频库可选，按 id 保存；
  设置表单去掉手填的 `libraries`，0.1.x 的旧值（库名或数字）首次运行自动迁移。
- 新增中文译名表：运行时从 jsDelivr 下载 MDCx `mapping_actor.xml`（GPL-3.0，不随包分发），ETag 条件请求 + 本地缓存；
  过滤 `【誤認注意】`、歧义名，`【同名異人】` 不用别名。可在设置里关闭。
- 匹配：展开叠字符号（々 / 〻 / ゝ / ゞ 等），`野野浦暖` 能对上 `野々浦暖`。
- 样本 25 位演员命中 15 → 24；MDCx 条目里头像库有的人：简体名 2397/3119 → 3119/3119，繁体名 803/1525 → 1525/1525。
- 只预览更稳：关掉 `dry_run` 后，入库事件与定时任务要等面板手动「立即写入一轮」解锁后才真正写入；新增「停止自动写入」。
- 面板：目标媒体库卡片、自动写入状态、译名表状态与「刷新译名表」。

## 0.1.0 - 2026-11-04

- 首个版本：用 gfriends 头像库给本地视频库（默认「小姐姐」）的演员补头像。
- 只改条目旁的 `<番号>.nfo`：已有 NFO 只加/换本插件拥有的 `<thumb>`，不变式检查保证其他节点不变；没有 NFO 时新建（只含 `<title>` 与档案里的全部演员）。
- 匹配：原名 → 空白/全半角 → 简繁日字形折叠（4496 组）→ 括号别名；从片名推断的候选只进「待确认」。
- 头像索引 `Filetree.json` 条件请求（ETag）+ gzip 传输 + 本地 gzip 缓存，源站故障时用旧索引。
- 默认只预览；台账、NFO 原文备份（插件私有目录）、单条/全部撤销。
- 定时任务、入库事件、手动运行；侧栏面板（全部输出经 textContent 转义）。
- 主程序不显示 NFO 头像时自动熔断：写入先探路一部，复核不显示就停手；主程序修好后自动续写并补刷新。
