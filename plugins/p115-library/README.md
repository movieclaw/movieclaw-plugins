# 115 网盘与 STRM 媒体库 2.8.2 · 安装说明

适配 MovieClaw v0.35.0（进程外插件，SDK ^1.0）。

**本版起 MovieClaw「插件 → 设置」页不再显示设置表单**——全部配置都在网页控制台完成，保存即时生效（插件不重启）。控制台为 CMS 风格左侧边栏导航：核心配置（115账号/STRM配置）、数据同步（全量/增量）、网盘文件、运行日志。覆盖升级后扫码凭据与 STRM 同步记录全部保留。

## 快速上手（必读）：先建媒体库，再同步

> **插件只能在 MovieClaw 已有媒体库的目录里创建 STRM。** 本插件申请的写入权限是「媒体库目录读写」——MovieClaw 只允许它写入**已配置为媒体库的目录（及其子目录）**。STRM 目录不在任何媒体库里，同步会报「STRM 目录写入被拒绝 / 没有获得访问 … 的授权」，一个文件也写不出来。

**第一步：准备目录**（填 MovieClaw 看得到的路径；Docker 部署填**容器内路径**）

- 例如 `/media/strm/电影`、`/media/strm/剧集`。目录要允许 MovieClaw 的运行用户写入（Linux 下目录属 root 时需 `chown` / `chmod`）。
- 建议 STRM 目录与真实视频目录分开，不要放在一起。

**第二步：在 MovieClaw 里新建媒体库，路径指向这个目录**

- MovieClaw → 媒体库 → 新建媒体库：电影选 `/media/strm/电影`，剧集选 `/media/strm/剧集`（也可以只建一个媒体库指向 `/media/strm`，下面的子目录都能写）。
- 已经建好插件、后来才加媒体库的：如果同步仍提示写入被拒绝，到 MovieClaw「插件」页把本插件停用再启用一次，让授权目录刷新。

**第三步：安装插件并登录 115**

- 安装并批准授权（见下方「安装」）→ 打开左侧边栏「115网盘」→「核心配置 → 115账号」扫码登录。

**第四步：配置同步目录**（「数据同步 → 全量同步」）

- 单目录：「115媒体库cid」点「点击输入」选网盘目录；「本地STRM目录」填**第二步媒体库里的路径**，如 `/media/strm/电影`。
- 多个目录（电影 / 剧集分开）：用「多目录映射」，每一条的本地目录都必须在某个媒体库之内，且相互不能相同或嵌套。
- 点「保存配置」。

**第五步：开始同步**

- 点「开始全量同步」。STRM 与图片 / NFO / 字幕会边扫边写进上面的目录。
- **全量同步完成后不会自动通知媒体库扫描**——请在 MovieClaw 里对该媒体库手动扫描一次。之后网盘有变动触发的**增量同步**会在有变化时自动通知 MovieClaw 扫描。

**常见问题**

| 现象 | 原因与处理 |
|---|---|
| 「STRM 目录写入被拒绝」「没有获得访问 … 的授权」 | 本地 STRM 目录不在任何媒体库里：按第二步新建媒体库指向它（或把目录挪进已有媒体库），必要时停用再启用插件 |
| 「Permission denied」「Errno 13」 | 目录在媒体库里，但操作系统不允许 MovieClaw 写入：检查目录属主 / 权限 |
| 同步完成但媒体库里看不到 | 全量同步不通知扫描：在 MovieClaw 里手动扫描该媒体库 |
| 路径填了宿主机路径（如 `/volume1/...`） | Docker 部署要填容器内路径（MovieClaw 里新建媒体库时看到的那个路径） |

**2.8.2 · 使用说明放进控制台**：左侧边栏最上方新增「使用说明」页（五步流程 + 常见问题，内容同上方「快速上手」，可点击直接跳到对应设置页）；**全新安装、还没配置同步目录时，打开控制台默认就显示这一页**；「全量同步」页顶部提示里也有「查看完整使用说明 →」入口。

**2.8.1 · 使用说明**：新增上方「快速上手（必读）」——**必须先在 MovieClaw 新建媒体库并指向 STRM 目录，插件才能在该目录下创建 STRM**；控制台「数据同步 → 全量同步」页顶部同步加了醒目提示，「本地STRM目录」与「多目录映射」的说明也写明了这一点。功能代码无改动。

**2.8.0 · 新功能：播放剧集时预取后续剧集直链，下一集秒开**：

- 每次点开一个 STRM，插件都要向 115 签发一次直链（排在「API 请求间隔」后面，约 1~3 秒）才能把播放器跳转过去。现在播放剧集时，插件会在**后台**把后面几集的直链提前签好：
  - **一次请求批量签发**（不额外占用多次请求间隔）；
  - 用**同一个播放器的 User-Agent** 签发——302 直连模式下 115 的直链和 UA 绑定，换 UA 会 403；中转模式按中转方式签发；
  - **缓存到链接自身的有效期**（直链里的 `t=` 过期时间，提前 5 分钟失效），而不是「直链缓存时间」的 10 分钟——看完 45 分钟的一集，下一集的链接仍然有效；
  - 同一集反复请求（拖动进度、读字幕轨）10 分钟内只预取一次；剩余有效期不足 20 分钟的链接会重新签发。
- **怎么找「下一集」**：按插件自己的同步记录，同一文件夹里的视频按文件名**自然排序**（S01E09 < S01E10），季末自动接下一季（Season 01 → Season 02）。文件夹里只有一个视频的（电影）不预取，也不会跳到别的电影。
- 设置：「STRM配置 → 预取后续剧集」，默认 **2 集**，可设 0~5，0 = 关闭。预取完全是后台尽力而为，失败不影响当前播放；运行日志会记一条「预取后续剧集直链 N 个」。

**2.7.13 · 只有增量同步通知媒体库扫描**：

- **增量同步**（115 事件触发、cron 定时、面板「开始增量同步」）：本轮有 STRM / 图片 / NFO / 字幕写入、更新或删除时，完成后通知 MovieClaw 扫描对应目录；没有任何变化则不通知。
- **全量同步**：只报告完成，不通知扫描（大批量入库请在 MovieClaw 里自行扫描）。
- 通知失败不算同步失败：5 秒后重试一次，仍失败则运行日志写明原因，下次增量同步自动补发。

**2.7.12 · 同步完成后不再通知 MovieClaw 扫描媒体库**：

- 同步写完 STRM 与图片/NFO/字幕、保存好记录即「完成」，不再向 MovieClaw 发「扫描媒体库」请求，也就不会再出现「媒体库扫描未启动」之类的提示。新内容由 MovieClaw 自己的定时扫描 / 实时监控或你手动扫描收录。
- 旧版本留下的「待扫描」标记会在下一次同步时自动清理。
- 插件权限列表**未改动**（仍包含媒体库扫描权限，只是不再使用），因此覆盖升级不需要在 MovieClaw 里重新批准授权。

**2.7.11 · 「媒体库扫描未启动」不再算同步失败**：

- 「STRM 已保存，但媒体库扫描未启动」出现在同步的**最后一步**：STRM 已全部写好、同步记录已保存，只是通知 MovieClaw 扫描媒体库时被拒。此前它被当作同步失败：后面的映射不再执行，MovieClaw 给出的原因也被丢掉。
- 现在：通知失败会 5 秒后重试一次；仍失败则在运行日志写明 MovieClaw 返回的原因与需要扫描的目录，标记「待扫描」（下次同步自动重发），**本轮照常完成并继续同步其余映射**。

**2.7.10 · 实时保存进度：插件意外退出也只丢几秒**：

- **之前**：进度每 2000 个文件或 60 秒保存一次，另在「停止 / 失败」时补存一次。但进程被直接结束（容器被杀、内存不足、宿主重启）时来不及补存，最多丢一分钟的进度；而且播放记录是批量落库的，崩溃前刚写的 STRM 在下次同步前可能放不出来。
- **现在**：
  - 进度**约每 3 秒或每 300 个文件**保存一次。保存方式改为反复改写同一个「尾记录」（满约 400 条才开新的一块），每次只需 1 次存储写入，几乎不增加开销；
  - 上一轮没有正常结束时，下一轮开始会根据已保存的进度**补齐全部播放记录**；
  - 播放接口兜底：找不到播放记录时，从已保存的同步进度里查回并修复，所以崩溃前刚写好的 STRM **不用等下次同步也能播**。
- 图片 / NFO / 字幕的进度同样实时保存。

**2.7.9 · 修复「STRM配置 → 是否保留文件后缀」说明文字错位**：2.7.7 加的说明被放在了两列布局之外，跑到了标签列下方；现已与其他选项对齐。新增面板结构测试：每个设置行必须是「标签 + 一个内容列」，此类错位会在打包前被拦下。

**2.7.8 · 修复：一个图片/字幕下载超时导致整轮同步失败（ReadTimeout）**：

- **现象**：运行日志「全量同步失败（耗时 0s，扫描 0）：STRM 生成失败（ReadTimeout）：无详细信息」，堆栈只有 httpx 内部。
- **根因**：图片/NFO/字幕从 115 CDN 下载这一步没有兜住网络异常；2.7.5 起附属文件改为边扫边下，某个 CDN 文件读取超时就把整轮同步带崩。（115 接口本身的请求一直有重试与限速等待，不受影响。）
- **修复**：
  - 附属文件下载：复用连接、连接 15 秒 / 读取 60 秒超时、最多 3 次尝试（CDN 拒绝 401/403/410 时自动重新签发直链），仍失败则**只跳过这一个文件**，运行日志汇总「N 个图片/NFO/字幕下载失败，下次同步自动重试」，STRM 不受影响；
  - 失败提示改为可读：网络类异常给出中文原因（如「网络读取超时」）和出错的插件代码位置，不再是「无详细信息」和 httpx 内部堆栈；
  - 同步历史里失败记录的耗时 / 扫描数改为真实值（之前失败一律显示 0s / 0）。

**2.7.7 · 同名冲突处理简化**：

- STRM 文件名照搬网盘：`电影.mkv` → `电影.strm`，目录结构原样对应。
- 同一目录里只差扩展名的两个视频（`电影.mkv` + `电影.mp4`）固定保留体积较大的那个（每次结果一致，不会来回改写）。**移除「同名冲突时 → 中止同步」选项**——它是唯一会因为一个重名文件卡住整次同步的地方；旧设置里的「中止」升级后按「保留较大」处理。
- 冲突**不再逐条写运行日志**（大库会把日志刷满），只在同步结果里显示数量，同步历史保留前 10 条明细。
- 想两个版本都保留：打开「STRM 保留文件后缀」，生成 `电影.mkv.strm` / `电影.mp4.strm`（切换后已有 STRM 换成新名字，媒体库需重新识别）。

**2.7.6 · 「单次扫描最大条目数」默认不限制**：

- 默认值改为 **0 = 不限制**，文件再多也照常同步。它现在只是可选的安全阀：填一个数后，映射目录在 115 上的文件总数超过它时，会在扫描第一页就停下并提示（防止误把整个网盘当媒体库）。
- 升级时，停留在旧默认值（100000 或 1000000）的安装会自动改为不限制；你手动填过的其他数值保持不变。
- 大库内存优化：极速扫描只记住要处理的视频/附属文件（不再记住每一个列出的文件 ID）；未变化文件直接沿用上次的记录对象，同步时不再在内存里同时放两份完整记录。

**2.7.5 · 图片 / NFO / 字幕完整跟随视频同步**：

- **之前**只同步两类：与视频**同名**的文件（`电影.nfo`、`电影.srt`）和 6 个固定文件名（poster.jpg / fanart.jpg / folder.jpg / cover.jpg / movie.nfo / tvshow.nfo），且只看视频**所在目录**。Emby / Jellyfin / Kodi / tinyMediaManager 的大部分刮削产物都被漏掉：`电影-poster.jpg`、`电影-fanart.jpg`、`S01E01-thumb.jpg`、`landscape.jpg`、`clearlogo.png`、`banner.jpg`、`.webp`，剧集目录里的 `tvshow.nfo` / `poster.jpg` / `season01-poster.jpg`，季目录的 `season.nfo`，以及 `extrafanart/`。而且附属文件要等整个网盘列完才开始下载，中途停止就一个都没有。
- **现在的规则**：凡是**含视频的目录、它的各级上级目录**（剧集 / 季 / 合集层），以及这些目录里的 `extrafanart` / `extrathumbs` 文件夹中的全部 `.nfo` `.jpg` `.jpeg` `.png` `.webp` `.tbn` 和字幕（`.srt` `.ass` `.ssa` `.vtt` `.sub` `.idx` `.sup`）都会同步到 STRM 目录的对应位置。**不含视频的目录（相册、资料等）不同步。**
- **边扫描边下载**：哪个目录一出现视频，它那一层和上级目录的附属文件就开始下载（直链每 100 个合并一次签发，8 路并发下载），不再等列表结束；每个附属文件单独记录进度，停止后保留，下次只补缺的。
- 网盘里附属文件没变（SHA1 相同）且本地还在时不重复下载；网盘更新后自动更新。本地已有但不是插件下载的同名文件（或被你改过的）**绝不覆盖**，只在日志里计数。开启「清理网盘已删除的 STRM」时，网盘删掉的附属文件也会同步删除（只删插件下载且未被改过的）。
- 开关仍是「数据同步 → 全量同步 → 图片/NFO/字幕同步」（默认启用）；单文件上限 20MB。

**2.7.4 · 同步中途停止 / 中断后保留进度，再次同步不必从头来**：

- **之前**：同步记录只在整轮成功结束时才保存。中途停止、失败或插件重启，已经写好的 STRM 虽然还在盘上，但没有记录——下次同步要把它们逐个重新签名、读回、核对，看起来就是「从头再来」。
- **现在**：
  - 同步过程中**每 2000 个文件或每 60 秒**把新完成的记录追加保存一次（只写增量，很轻）；
  - 点「停止」、同步失败、插件关闭时**再立即保存一次**，运行日志会写「已保存进度（本轮共记录 N 个已完成文件）」；
  - 再次同步时，已完成的文件直接走快速路径（不签名、不重写），只处理剩下的；
  - **升级前（2.7.3 及更早）已经停掉、没留下进度的那次同步**：只要播放地址配置没变，盘上已写好的 STRM 会按内容直接认领（不再逐个签名），并顺带记录进度。
- 115 侧的文件列表每次同步仍会从头分页列一遍（10 万文件约 2~3 分钟，受「API 请求间隔」限制），这部分无法续传——列表顺序会随网盘变动而变化，续传反而可能漏文件。
- 「停止同步」等待收尾的上限从 15 秒放宽到 60 秒，确保进度落盘后再回报「已停止」。

**2.7.3 · 修复升级后自动开跑同步 / 停止同步无效 + 写入再提速**：

- **插件升级 / 重启后不再自己开始同步**：根因是同步被打断（点「停止」、插件升级时进程被结束）时会写一个「待同步」标记，插件下一次启动就按标记把同步又跑起来；另外 cron 错过的时间点会在启动时立即补跑。现在：启动（含升级、宿主重启、保存配置）后的第一轮**只记录事件基线**、清掉残留标记；cron 从启动时刻起算，不补跑错过的点。只有你点「开始」、115 网盘有新变动、或 cron 到点才会同步。
- **「停止同步」对任何来源的同步都有效**：此前只能停掉面板按钮发起的同步，由 cron / 115 事件 / 上述标记触发的同步根本停不下来，停下的同步又会因为「待同步」标记在 1 分钟内自动重跑。现在同步在独立任务里运行，停止会真正等它结束再回报；停止不算失败、不留重跑标记、已写入的 STRM 保留且立即可播。失败的同步也不再每分钟自动重试，等下一个 cron 时间点。
- **写入再提速（主要针对宿主处理慢的情况）**：每个新 STRM 的宿主调用从约 6.6 次降到约 3 次：
  - 不再为每个文件写「写入意图」记录：是否插件生成改为直接看文件内容（插件签发的 `/play/<id>` 链接）判断，手工改过的文件照旧绝不覆盖；
  - 播放记录改为分 1024 片批量落库（首次同步 2 万文件约 1000 次写入，而不是 2 万次）；未落库前播放接口直接从内存取，写完即可播；
  - 先看上级目录的列表判断子目录是否存在：首次同步不再为每个电影目录单独 `listdir`，已存在的目录不再 `makedirs`；新目录的 `makedirs` 与签名并发；
  - 新文件直接写入（不再「临时文件 + 改名」两步），覆盖已有文件仍走原子替换。

**2.7.2 · 边扫描边写入（写入与 115 列表并行）**：

- **之前**：极速扫描要等 115 把整个目录全部列完（大库要几分钟，主要在等「API 请求间隔」），才开始写第一个 STRM——这段时间写入完全闲着。
- **现在**：目录树先取回（1~2 次请求），之后**每拿到一页文件（1150 条）就立即交给写入**，写入与后续翻页同时进行；STRM 目录随扫描实时增长。实测（模拟 8000 个视频首次同步）总耗时 89 秒 → 48 秒，写入时间基本被列表时间完全覆盖。
- **写入并发 8 → 16，按输出路径分片**：同一个 .strm 永远由同一个写入任务处理，同名冲突（`X.mkv` + `X.mp4`）边到边裁定——较大的后到会在同一任务里覆盖较小的，最终结果与到达顺序无关，被替换者的播放记录同步清理。
- **新文件少两次宿主往返**：签名与本地存在性检查并发；本地没有文件时不再读取「写入意图」；播放记录与写入意图两次写入并发（仍保证先于 STRM 落盘）。
- 逐目录扫描（legacy）行为不变。

**2.7.1 · 大库（10 万文件以上）极速扫描修复**：

- **现象**：运行日志出现「快速扫描不可用（达到最大条目限制，请缩小同步目录），本次改用逐目录扫描」。实际上极速扫描在 115 上已经工作，是同步目录内文件总数（115 统计的全部文件，含图片/NFO/字幕）超过了「单次扫描最大条目数」的旧默认值 100000。该项此前在控制台里根本没有输入框，用户无法调整；而且超限后错误地退回了逐目录扫描（同样会在几小时后撞到同一个上限）。
- **修复**：
  - 默认上限改为 **1000000**（可设到 5000000）；仍停留在旧默认 100000 的安装升级后自动迁移。控制台「数据同步 → 全量同步」新增「单次扫描最大条目数」输入框。
  - 极速扫描在**第一页**就用 115 返回的总数做判断，超限直接报错并给出建议值，**不再退回逐目录扫描**白跑几小时。
  - 列出时只把视频和需要的附属文件留在内存里（其余图片/杂项边列边丢），大库内存占用大幅下降；进度按 115 实际列出的数量显示。
  - 大库分页要几分钟，期间网盘有上传导致计数变化时不再整轮重来：按 ID 去重继续，并且**本轮不做删除清理**（避免误删），被挤过的文件下一轮补上。

**2.7.0 · 同步提速重做：极速扫描 + 未变化文件零开销**：

之前慢的根源不在写文件，而在**扫描方式**：旧版逐个目录调用 115 列表接口，每次都要排队等「API 请求间隔」（默认 1.5 秒）。一个 1500 部电影的库至少 1500+ 次请求 ≈ 40 分钟起步，而且每次增量/事件触发都要再完整走一遍。

- **极速扫描（默认）**：改用 p115client 的整树遍历契约——`cur=0 + show_dir=0` 一次性分页列出整个目录下的**全部文件**（每页 1150 条），目录名用 `downfolders` 目录树接口一次取回（每页 5000 个目录）。**请求数只和文件总数有关，和目录数量无关**：5 万文件约 50 次请求。目录树接口不可用时，只对「未知目录」逐个查面包屑兜底；整树列表接口本身不可用时自动退回逐目录扫描并写日志。可在「数据同步 → 全量同步 → 网盘扫描方式」切回旧方式排查。
- **未变化文件零开销**：上一次同步干净完成、播放地址规则没变时，115 侧身份（ID/大小/SHA1/提取码/修改时间）和路径都没变的文件直接沿用记录——不再逐个签名、不再逐个写「写入意图 / 播放记录」；快速模式下本地存在性按目录一次 `listdir` 判断。上次同步中途中断，或地址/格式/存在策略改过，下一次自动走完整校验，自愈逻辑不变。
- **附属文件不再每次全量读回**：海报/NFO/字幕在 115 的 SHA1 未变且本地文件仍在时信任记录，不再每轮把几百 KB 的图片经宿主读一遍算哈希。
- **修复：状态上报节流从未生效**：实际运行的 `AutoEngine` 覆盖了上报方法，每处理一个文件都把整份状态写一次宿主存储；现已按 0.7 秒节流。
- **修复：大库收尾可能丢文件**：扫描结束后写入队列只给 10 秒收尾，宿主慢时队列里剩下的文件会被直接取消（同步却显示成功）；现在等全部写完。
- **单个被手改的 STRM 不再让整次同步失败**：照旧绝不覆盖，但只跳过该文件、计入「跳过」并写日志，其余文件正常同步。空文件（写入中断留下的）视为插件文件自动修复。
- **其他减负**：115 请求复用连接（不再每个请求重新握手）；写 STRM 不再 fsync、成功路径少一次存在性检查；「需要媒体库扫描」标记每个映射只写一次；未变化的库不再重写全部同步记录分片；进度日志改为每 20 秒一条（原来每 10 个文件一条，会把 100 条的运行日志冲掉）；写入并发 4 → 8。
- **断点续传**只在「逐目录扫描」下生效（极速扫描全量一遍只需几十次请求，不再需要跳过目录，也就不会再出现「跳过的目录漏掉新文件」）。

**2.6.3 · 断点实时保存 + 修复插件启动后自动同步**：

- **断点改为实时保存**：之前断点每 2 秒才落一次、且每次全量重写，同步一快中间那几次就被跳过，看起来像「点停止才保存」。现在改为**增量追加**——每完成一个目录就立刻追加一小片（只写新增目录，不重写全量），面板「断点记录」数字随扫描实时增长；节点攒多了自动合并。
- **修复插件启动后自动跑同步**：此前插件一加载，事件指纹「从无到有」、以及 cron 从「从未同步」算出的过去时间，都会把同步自动触发。现在首次启动只记录事件基线、不触发同步，只有你点「开始」、网盘有变动、或 cron 到点才真正同步。

**2.6.2 · 修复：断点记录超过宿主 64 KB 上限导致同步失败**：

- 现象：大库（目录多）全量同步时报「STRM 生成失败（ValueError）：值超过 64 KB，请存文件、这里存引用」——断点记录把「已完成目录集合」塞进单个数据值，目录一多就超宿主 64 KB 上限。
- 修复：断点记录改为**分片存储**（像同步记录一样拆成多个小片，每片 <60 KB），根记录只存分片列表与总数；读写、覆盖、清理全部适配。旧版已成功写入的小断点仍可读取，不会丢。

**2.6.1 · 大库提速 + 全量断点续传（对 2.5.x 系列的正确重做）**：

- 面板「数据同步」状态区新增**「断点记录」**一行，直接显示已记录多少个目录——排查「不跳过」时先看它：为 0 说明第一次全量还没跑完（没积累断点），大于 0 才会跳过。
- 同步失败/手动停止时也**立即保留断点**（之前只靠节流落库，最近几秒的进度可能丢）。

- **多并发写入**：写侧从单线程改为 4 个并发 worker（有界队列 + 正确收尾），STRM 生成吞吐大幅提升；同名冲突（`X.mkv` + `X.mp4`）改为**目录枚举完时当场消解、只写胜者**，不再先写小文件再被大文件覆盖。
- **全量断点续传（本地记录，不碰 115 星标）**：每次同步把「已完整写完的目录」记进插件本地数据；**全量同步中断后再次全量会跳过这些已完成目录，不必从头重扫**。进度在扫描过程中持续落盘，进程崩溃也只丢最近几秒的目录进度。断点记录与 115 账号无关、不污染网盘。
  - **注意**：续传跳过的目录，其「上次同步之后网盘里新增的文件」要等**增量同步**或「清理断点后重新全量」才会补上——这是「跳过重扫」的必然取舍。网盘有大动作（大量上传/改名）后，建议点一次「🗑️ 清理断点」再做全量，或直接跑增量。
- **停止同步**：同步运行中面板出现「⏸ 停止同步」，随时可暂停；已写 STRM 与断点进度都保留，下次全量继续。
- **进度日志**：运行日志每 10 个文件记一条进度（写入/未变化 + 当前文件），大库同步时能看见在处理哪个文件。
- **启动不再强制全量**：插件加载后不再自动跑一遍全量（大库以前一加载就卡），但**事件监控与定时补扫照常运行**——网盘移动/上传、cron 到点仍会触发同步。
- 修复了 2.5.x 系列的实现问题（4 个写入 worker 只有 1 个结束信号导致成功也判失败、星标 API 与 115 契约不符、并发写破坏同名冲突裁定等）。

**2.4.1 · 网页入口收敛为一个：侧边栏「115网盘」**：

- 支持插件网页的 MovieClaw（≥ v0.42.0）左侧边栏只保留一个入口 **「115网盘」（`/apps/p115-library`）**，点开就是完整控制台。

**2.4.0 · 撞到 115 风控自动等待后继续 + 写入与扫描真正并行（大库不再"写到一半就不动"）**：

- **现场现象**：大库同步时「写入 N」卡在某个数字不再增长、只有扫描数在涨；或同步在某个数量后整次失败（此前只能把错误的锅甩给"格式/配置"，日志里真正的话是「操作太频繁」）。
- **① 风控不再终结同步**：115 返回**限流/繁忙**（错误码 `590075 操作太频繁`、`990003 请稍后再试`、`990005 同类任务处理中`）、HTTP `408/429/5xx`、网络抖动或返回非 JSON（限速页）时，插件**原地等待再继续**：首次等待 30 秒，之后按 2 倍递增（30 → 60 → 120…，单次最长 600 秒），最多 5 次（两项均可在「核心配置 → 115账号」调整）。**已生成的 STRM 全部保留，扫描从断点继续，不必从头重来。**
  - **凭据类错误**（990001 登录超时等）**不等待**，照旧立即报错——那种错误等也等不来。
  - 等待期间「115同步」页橙色显示 **⏸ 115 限速冷却中：剩余 Xs**（含原因与第几次等待），一眼可辨「在等」还是「卡死」。
- **② 写入与扫描并行**：此前每写一个 STRM 都要回到网盘线程继续枚举——单个文件 6~8 次宿主往返（签发 + 两条记录 + 建目录 + 写盘 + fsync + 重命名）会把整轮枚举明显拖慢，文件树明显跟不上扫描。现在**扫描与写入是两个并发任务**（队列限深 64）：网盘侧继续翻页的同时写入侧同步落盘，STRM 随扫描生长；目录创建结果当轮复用，省掉重复的建目录往返；状态上报合并（≤1.5 次/秒），不再与网盘请求抢 IPC。
- **③ "写入数不涨"不再是谜**：已经在盘且与同步记录一致的文件计入**未变化**而非重写（这是设计如此，不是卡住）；此时面板会显示一行灰色说明"正在边扫描边核对，遇到新文件或有变化的文件会立即生成"。
- **④ 同步结束汇总**：本次若触发过限速，运行日志会追加一条汇总（「本次同步遇到 115 限速 N 次，累计等待 X 秒后自动继续」），方便据此把「API请求间隔」调到合适值（大库建议 2~3 秒）。
- **配置建议**：大库（数千以上 STRM）把「API请求间隔」调到 2~3 秒，可显著减少触发限速；真撞上限速时默认策略已能自愈，无需人工介入。

**2.3.1 · 修复：宿主未配置「外部访问地址」时同步报「STRM 生成失败（ValueError）」**：

- **现象**：全量/增量同步失败，报错只有「STRM 生成失败（ValueError），请查看日志或检查配置」，看不出真实原因。
- **根因**：生成 STRM 里的播放地址需要完整链接。MovieClaw 在「设置 → 应用」的**外部访问地址**为空时，签发接口会返回一条带明确指引的错误（「没有配置外部访问地址（设置 → 应用）」）——这条错误到达插件后真实消息被兜底逻辑丢弃，只剩异常类名，变成无用的「（ValueError）」。宿主重装/迁移/清空设置后极易触发。
- **修复**：
  - 同步失败时**完整保留真实错误消息**（同步失败（类型）：具体原因），意外异常还会把堆栈尾部写进运行日志，现场问题可直接从面板复制定位；
  - **配置了「strm直连地址」后完全不再依赖宿主的外部访问地址**——签发改走相对链接、自行拼接你填写的地址，宿主设置留空也能正常同步（地址替换与配置页示例地址同步适配）；
  - 两者都没配置时，报错直接给出两条修复路径：① MovieClaw「设置 → 应用」填写外部访问地址；② 本插件「STRM配置 → strm直连地址」填写外网可达地址。
- **当前正受此问题影响的用户**：升级到本版后，去 MovieClaw「设置 → 应用」把**外部访问地址**填上（如 `http://你的IP:9577`，须为浏览器访问 MovieClaw 用的地址），或在插件「STRM配置」页填「strm直连地址」，任选其一后重跑同步即可。

**2.3.0 · 边扫描边生成 + 快速模式对全量生效（大库同步体验重构）**：

- **边扫描边生成**：同步不再是「扫完全部目录才开始写」——每枚举到一个视频就立即校验并写出对应 STRM，**文件树随扫描实时生长、写好即可播放**，不用等整个网盘枚举完。中途失败（网络/分页异常）已写出的文件保留在盘，下轮同步自动自愈补齐（同步记录只在成功时保存，部分文件树不会被误当成完整结果）。
- **快速模式（极速）对全量同步同样生效**：此前极速模式只加速增量；现在全量勾选极速后同样**信任同步记录、跳过未变化文件的读回校验**，大库全量只付枚举时间。两种模式都只重写有差异的文件。普通模式仍逐个读回校验（可发现并拒绝被外部改动的文件），正确性最强。
- **同名冲突当场消解**：同一目录里 `X.mkv + X.mp4` 这类冲突，仍按「自动保留较大」处理；先写出的较小版本会被较大版本当场重写，被淘汰者的播放记录同步清理，不留垃圾数据。
- **附属文件（字幕/NFO/海报）下载时机不变**：在枚举完成后统一配对下载（字幕可能在视频之后才被枚举到），已有缓存逻辑不受影响。

**2.2.1 · 修复：单个网盘条目异常导致全量同步失败（「115 文件数据格式不合规，同步已停止」）**：

- **现象**：全量/增量同步刚启动（耗时 0s、扫描 0）即失败，报「115 文件数据格式不合规，同步已停止」，且不指明是哪个文件、什么原因。
- **根因**：此前的实现对网盘列表里**每一条**数据做严格校验，任何一条字段异常（如文件名含 `\`、ID 非数字、字段缺失等边角数据）都会中止整个同步。生产实现（OpenList/115driver）对单条数据一律容错跳过，从不因此失败。
- **修复**：单条异常降级为**跳过 + 日志 + 计数**——好文件照常入库，同步统计新增「跳过 N」计数，面板同步状态出现橙色提示，运行日志逐条记录异常原因与该条目的字段诊断（如 `n='xxx' fid=... 字段=[...]`），方便定位到具体网盘文件（通常是某个名称特殊的文件，改名或删除即可彻底消除）。目录判定同时与生产实现对齐（空 fid 视为目录）。
- **保留的中止保护**：结构性异常（分页损坏、目录不符、条目重复）与「整页数据全部无法解析」（意味着 115 系统性更改了响应格式）仍然立即中止并带诊断，不会"成功"同步出一个空库。

**2.1.1 · 修复：未登录时插件报「请先扫码」而无法进入面板/替换**：

- **现象**：全新安装（或宿主数据未迁移的新部署）在未扫码登录时，插件加载与面板状态接口直接报「请先扫码登录 115」异常，用户误以为扫码登录被移除。扫码登录功能完好，一直都在——面板「核心配置 → 115账号」页。

- **修复**：未登录时插件正常启动，面板同步状态显示「等待登录：请先扫码登录 115」；「地址替换」未登录时给出明确指引（先到 115账号 页登录）；**扫码成功后立即自动开始首次同步**（此前要等下一轮定时周期）。

**2.1.0 · 存量 STRM 地址替换（外网地址变更后几秒修复播放）**：

- **场景**：MovieClaw 的外网地址（域名/IP/端口）变更后，已生成的存量 STRM 里仍是旧地址，播放器全部无法访问。此前的恢复方式是重新全量同步（要完整枚举网盘，受 API 间隔节流，大库耗时数分钟到更久）。
- **新工具**：「核心配置 → STRM配置 → 存量STRM地址替换」。先点「🔍 预览」统计可替换数量（不修改任何文件），再点「✎ 执行替换」把插件生成的存量 STRM 内地址统一刷新为**当前 strm直连地址**（留空则当前访问地址）——路径与签名原样保留，只要新地址能路由回本 MovieClaw，替换后立即可播。
- **零 115 流量**：替换完全由插件本地同步记录驱动，不访问网盘、不重新枚举，几千个 STRM 也只需几秒到几十秒。替换后同步记录同步对齐，下次增量核对显示「未变化」，零重复写入。
- **安全边界**：只处理**插件生成且内容与记录一致**的 STRM；被手工修改过的文件计数跳过、绝不触碰；已停用映射目录下的文件不受影响。运行日志记录每次预览/执行的完整计数。

**2.0.2 · 全量同步提速：校验全部、只重写有差异的**：

- **改动**：此前全量同步对**每个**文件无条件重写（即使内容一字不差）；现在全量仍然**逐个校验**（所有权与内容），但只有记录或内容有差异的文件才写入——健康库的全量从「重写 N 个文件」变为「全部校验、零写入」。
- **修复能力不损失**：文件缺失 → 重建；播放地址/直连格式等配置变化 → 全量重写为新地址；同步记录损坏 → 重建；用户手工修改过的文件依旧拒绝覆盖（防误删语义不变）。
- **速度说明**：快速模式（信任同步记录、跳过未变化文件的内容校验）只对**增量**同步生效；全量与增量的耗时大头都是网盘全量枚举（受 API 请求间隔节流，属风控约束）。日常增删改由事件监控在约 1 分钟内定点核对单个目录完成，无需频繁全量。

**2.0.1 · 授权再精简：不再申请 `/media/strm`，STRM 目录放媒体库内即可**：

- **机制**：MovieClaw 的 `library` 授权覆盖**所有已配置媒体库的目录**（含其下任意深度的子目录，含运行中新建的目录）。你只需在媒体库根下自建 STRM 目录（如 `/media/strm`），插件即可直接读写——**无需在插件清单单独申请路径**。
- **前提**：插件设置中的「本地STRM目录」（含多目录映射）必须位于 MovieClaw 已配置媒体库的目录**之内**；库外路径会被宿主沙箱拒绝写入（同步会给出明确报错与指引）。
- **升级**：从 2.0.0 及更早版本升级需在 MovieClaw「设置 → 插件」重新批准授权（授权列表减少了一个路径）。

**2.0.0 · 移除上传功能（重大变更，本地→网盘上传链路整体下线）**：

- **动机**：1.8.0 起事件监控已覆盖**全部** 115 操作类型——用 115 官方客户端、网页或任何设备上传/移动文件到监控库，插件都能在约 1 分钟内自动生成 STRM。本地→网盘的上传链路（整理目录扫描、分片上传、上传管理面板）已无必要，反而持续带来会话过期、入账确认等复杂故障面。
- **移除内容**：「监控上传」面板页（整理目录、自动上传、检查间隔、排除目录等设置与上传队列管理）、上传相关全部接口；本地附属文件不再随视频上传——附属文件请直接放网盘（与视频同目录），插件会经 115 直链下载补齐到 STRM 目录。
- **保留并强化为唯一入库方式**：**在 115 网盘侧**上传或移动文件（官方客户端/网页均可）→ 事件监控即时触发增量核对 → 自动生成 STRM 与附属文件。定时增量同步（cron）继续兜底。
- **新增使用要求**：如需下载器自动入库，请用 115 官方客户端或 rclone/OpenList 等工具直接写入网盘监控目录。
- **授权精简**：插件清单不再申请 `/media/download`、`/media/link`、`staging` 授权（上传源目录已不存在），只保留媒体库根与 `/media/strm` 读写。**升级安装时 MovieClaw 会要求重新确认授权**（包先进待批准状态，批准后生效）。
- **升级迁移**：旧的整理目录/上传设置与上传历史记录自动失效（不再读取，留在插件存储中无害）；从任何 1.6.x–1.8.1 版本覆盖升级即可。

**1.8.0 · 115 事件监控升级为全操作类型（移动入库即生成 STRM）**：

- 事件轮询拉取 115 操作记录的**全部类型**（上传/移动/接收/新建目录/删除/目录改名等），浏览/星标类只读操作按生产实践忽略——在 115 端看视频、标星不会误触发同步。**移动文件到监控库 → 下一轮事件轮询（默认 60 秒内）触发目录核对 → 自动生成 STRM**。
- 每条事件按操作类型写入运行日志（来源「115事件」）；紧随其后的「同步」条目就是这条事件引发的完整操作流程。
- 契约依据 p115client 生产实现；115 平台自身不采集「复制文件/文件改名」事件，这两类由定时增量兜底。

**1.7.9 · 修复「同步状态卡住」（宿主扫描 RPC 无限挂起）**：

- **根因**：同步收尾要通知宿主启动媒体库扫描（`library.scan.start`）与查询媒体库列表（`library.list`）——这两个宿主 RPC 没有超时。宿主媒体库正忙时插件侧无限挂起：锁永不释放、状态永远「同步中」、手动同步全部 409。
- **修复**：全部宿主 RPC 加限时（扫描 120 秒、列表 30/60 秒），超时**不判同步失败**（STRM 已落盘），保留「待扫描」标记下轮重试；同步中面板每 5 秒显示实时进度（已扫描 N · 写入 N · 已运行 Ns）。升级即重启进程，锁自动清空。

**1.7.8 · 同步历史详细汇报**：每条历史分三层——总览行（耗时/扫描数/写入/未变化/附属/清理/冲突）、每映射缩进行、冲突明细橙行（胜者与落选者的完整路径与体积，最多 10 条）；失败红行显示原因。

**1.7.7 · 同名 STRM 冲突不再拦死同步**：同目录两个不同格式的同名视频（X.mkv 与 X.mp4）压成同一 .strm 时——默认「自动保留较大」（确定性排序，跨运行稳定；明细写运行日志）；也可选「中止同步」（报错点名两个文件）。

**1.7.5 · 直链缓存（修复字幕加载慢）+ 播放拉流日志**：签发的 115 直链按「文件+UA+用途」缓存复用（默认 10 分钟，可调 1~60 分钟）——播放器拖进度、读字幕轨的连续请求零 115 往返；「服务器中转」遇 CDN 401/403/410 自动重签重试。播放成功路径也进运行日志（302 直连/中转拉流/缓存命中）。

**1.7.4 · 修复 CDN 拉流 403（签发 UA 精确重放）**：115 的 f=1 直链绑定签发 UA；所有服务器侧拉流显式携带签发 UA（含空 UA）+ 账号 Cookie + downurl 响应头；302 改按请求方（播放器）UA 签发（alist 生产模型）。播放诊断支持可选播放器 UA 实测。

**1.7.3 · 修复 302 直链签发（m115 协议）**：完整实现 alist/OpenList 所依赖的 m115 加密协议（XOR 种子表 + RSA 信封），签发策略链升级为协议×UA 矩阵；响应体兼容 ECDH 信封（AES-CBC + LZ4）。

**1.7.2 · 面板 JS 语法静态校验**：发布流程新增 node --check + 元素 ID 交叉校验，面板脚本语法错误在测试阶段拦截。

更早版本（1.6.x 多目录映射/运行历史/配置导出导入、1.5.x 设置私有存储、1.4.x cron 调度）详见历史版本安装说明。

## 安装

1. MovieClaw → 系统 → 插件 → 上传插件包，选择 `p115-library-2.8.2-movieclaw-v0.35.0.zip`（`.mcplugin` 为同一文件，二选一）。
2. 安装时批准权限：`library.scan.start`、`library.list`、**媒体库目录读写**、网络访问。2.0.1 起不再申请 `/media/strm` 等绝对路径——STRM 目录在媒体库内自建即可（见上方 2.0.1 节）。**从 1.6.x–2.0.0 升级时授权列表有变化（减少路径），需在 MovieClaw「设置 → 插件」重新确认**。
3. 安装后 MovieClaw 插件设置页没有表单是**有意为之**：全部配置都在网页控制台完成（见下方入口）。

## 控制台入口

**唯一推荐入口：MovieClaw 左侧边栏「115网盘」**（地址 `/apps/p115-library`）。安装批准时勾选「加到侧边栏」即可看到（默认勾选）。

## 页面说明

### 核心配置 → 115账号
- **115 Cookie**：扫码登录后自动填充；也可手动粘贴后保存生效。右侧「✓ 检测可用性」实时验证并显示账号与容量。
- **cookie对应设备类型**：下拉选择，默认微信小程序。「▦ 二维码登录」弹窗展示二维码，轮询扫码状态；登录异常时点「✚ 网络诊断」区分网络/通道/凭据问题。
- **API User-Agent**：扫码登录无需填写；手动粘贴 Cookie 时填写获取该 Cookie 的浏览器/客户端 UA，留空使用 Mozilla/5.0。
- **API请求间隔**：默认 1.5 秒，调大可降低风控概率（大库建议 2~3 秒）。
- **撞到风控后**：等待秒数后自动继续（默认首次 30 秒，之后翻倍，单次最长 600 秒）＋最多重试次数（默认 5 次，填 0 = 不重试立即失败）。等待期间同步不失败、已生成的 STRM 不丢，面板显示剩余等待时间。

### 核心配置 → STRM配置
- **strm直连地址**：留空 = 按当前访问地址自动签发；外网播放时填外网可达地址（须能路由回本 MovieClaw 服务）。
- **存量STRM地址替换**（2.1.0 新增）：外网地址变更后，点「🔍 预览」查看可替换数量（不修改文件），再点「✎ 执行替换」把存量 STRM 内地址刷新为当前直连地址——零 115 流量、路径与签名保留、几秒完成；只处理插件生成且未被手工修改的文件。
- **strm直连格式**：`pick_code`（仅播放地址）/ `pick_code_name`（地址后追加 `?/文件名`，便于播放器识别）。
- **是否保留文件后缀**：是 → `影片.mkv.strm`；否 → `影片.strm`（默认）。
- **strm文件本地存在时**：覆盖生成（仅限插件生成且未被手工修改的文件）/ 直接跳过。
- **同名冲突时**：`自动保留较大`（默认）/ `中止同步`（报错点名两个文件）。
- **播放方式**：`302 直连`（默认，服务器不消耗带宽）/ `服务器中转`（alist 代理模式，兼容所有播放器与受限直链；302 异常时先切换此项）。
- **直链缓存时间**：默认 10 分钟（1~60 可调）；播放中偶发直链过期报错时可调小。
- **strm生成示例**：只读，实时预览最终 URL。

### 数据同步 → 全量同步
- **同步模式**：普通模式（校验已有 STRM 内容）/ 快速模式（信任同步记录，适合大目录）。
- **115媒体库cid / 本地STRM目录**（单目录）：可直接输入，或点「点击输入」打开网盘目录树选择器。**本地STRM目录必须位于 MovieClaw 已配置媒体库的目录之内**（2.0.1 起插件只申请媒体库读写授权，库外路径会被拒绝写入；在媒体库根下自建子目录即可）。
- **多目录映射**：最多 8 条「115 目录 → 本地 STRM 目录」，各自独立同步；配置后单目录被忽略；目录之间不能相同或嵌套。
- **视频文件后缀**：标签式多选，回车添加、× 删除。
- **最小视频（MB）**：小于该体积的视频不生成 STRM，0 为不限制。
- **附属文件同步**：网盘中视频旁的附属文件（字幕/NFO/海报，含其他客户端上传的）经 115 直链下载复制到 STRM 目录对应位置（单文件 ≤20MB，云端变更按 sha1 自动跟进；用户改过的文件绝不覆盖）。**2.0.0 起这是附属文件的唯一入库方式——附属文件直接放网盘即可。**
- **清理网盘已删除的STRM**：核对确认网盘已删除后，移除插件生成且未被修改的 STRM 与附属副本；默认关闭只增不删。
- **⬇ 导出配置 / ⬆ 导入配置**：备份为 JSON（不含 Cookie），导入校验通过后立即生效。
- **开始全量同步**：对全部映射完整枚举并逐个校验，只重写有差异的文件（2.0.2 起；健康库全量零写入）；状态区实时显示进度。**2.4.0 起扫描与写入并行**：STRM 随扫描即时生成，撞到 115 限速会自动等待后接着跑（面板显示剩余等待秒数），中途也已生成的文件不会丢。
- **同步耗时**：大头是网盘目录枚举（受「API请求间隔」节流，这是 115 的风控约束）。2.4.0 之后写入不再占用枚举时间；健康库的重复全量以「未变化」为主，不再重复写盘。

### 数据同步 → 增量同步
- **同步任务cron表达式**：5 段式，默认 `*/20 8-23 * * *`；下方实时计算最近 5 次运行时间。
- 115 生活事件**即时触发**增量核对，cron 仅作定时兜底。
- **监控115生活事件 / 生活事件检查间隔**：监测网盘全部操作事件（上传/移动/接收/新建目录/删除/改名等，浏览类忽略）并即时触发目录核对——**在 115 网盘侧上传或移动文件到监控库后，约 1 分钟内自动生成 STRM**。
- **开始增量同步**：立即执行一次增量核对（只写变化）。

### 运行日志
- **运行事件**：插件启动、登录、配置变更、同步、**播放**（302 直连/中转拉流/下载直链及失败原因）、**115事件**（逐条记录网盘操作类型、文件名与体积）的关键事件；红色 = 出错，橙色 = 警告。
- **同步历史**：最近 20 次全量/增量运行的分层明细（总览行含耗时/扫描数，每映射缩进行，冲突明细行），失败原因红色显示。

### 网盘文件
- 按 CID 浏览 115 目录；文件行支持「下载」（302 或中转）与「诊断」（直链签发 + CDN 拉流矩阵探测，302 播放异常时用它取回报错详情）。开启「允许修改网盘文件」后可新建目录/改名/移动/复制/移到回收站。

### 保存与重置
- 每页底部「💾 保存配置」：校验通过后写入插件私有存储并**立即生效**——引擎热切换配置，插件不重启。
- 「↻ 重置配置」：恢复本页默认值；115账号页重置会二次确认是否同时清除 Cookie（退出登录）。

## 防误删设计
- 只增不删为默认；清理开关需显式开启。
- 清理/覆盖仅针对「插件生成且内容与记录一致」的文件；被手工新建或修改的文件一律保留并报错提示。
- 网盘文件重新出现后，被清理的 STRM 会在下次核对时自动重建。

## 未登录门控
- 尚未登录 115 时：全量/增量页的「点击输入」「开始全量同步」「开始增量同步」按钮置灰禁用，页面顶部橙色横幅提供跳转登录的快捷链接；登录成功后自动解禁。
