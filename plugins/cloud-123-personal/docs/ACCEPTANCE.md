# 用户自行进行的最小隔离验收

这些是后续完整验收步骤，本次PR准备未执行。已知alpha.5目录选择复测反馈不替代下面其他项目。请使用独立测试宿主及专用测试目录，保留本地原件；不要在生产库第一次试运行。不要向开发者提供手机号、密码、token、请求头、签名URL或HAR文件。

## 1. 准备与登录

用户自行安装最新测试包到MovieClaw v0.41.0（drive-backends1.5、plugin-data1.0）的隔离实例。通过宿主正式表单登录专用账号。遇验证码在官方客户端处理；本插件不绕过。先确认账号信息及目录选择器正常，错误时只记录SDK错误类别与时间。

## 2. 扫描完整性

在专用目录放置：至少201个小文件、两级子目录、空目录、非视频文件、中文文件名。通过宿主执行扫描，逐项对比数量、路径与空目录ID。扫描期间不改动目录。再在隔离条件下中断网络，确认失败不会被当作空目录或完成扫描。恢复网络后重新完整扫描。

逐目录遍历不是原生整树接口；规模增大时会消耗更多请求配额。超过安全上限时缩小根目录，不能把上限处的部分数据当结果。

## 3. 上传日志恢复

本地生成普通测试文件，建议至少40MiB以覆盖多片（实际SliceSize由服务返回）；避免上传唯一副本。通过宿主上传，在一片确认后停止该隔离插件进程，再启动，确认继续原会话、最终大小和MD5一致。重复同一个已完成任务，应重新核验原远端文件，不创建副本。

另测单片文件、空文件、同名不同内容冲突；将完成文件移动/改名/删除后重试原任务，应明确报错，不能复用旧缓存。仅在可控测试环境注入丢响应：PUT丢确认应重传同片；合并丢确认应停止并提示结果不确定。不要手动清空插件日志强行重试，不要开启多个写入实例。

如遇`initializing`或`committing`不确定状态，保留日志和本地文件，在官方客户端检查测试对象，仅记录“存在/缺失/可下载/大小是否相符”等结论。该观察还不能自动授权插件重放合并；需要可靠服务证据后才添加判断。

## 4. 下载

用实际播放器UA获取原文件链接，验证播放；300秒内检查宿主复用链接，过期后重新取链。记录是否出现中转页面、UA限制或签名到期，不记录URL本身。

## 5. 可选：确认个人分片列表响应结构

目前公开真实证据仅覆盖新会话`Parts:null`；非空返回结构未确认。若用户愿意自行在官方网页开发者工具中观察测试上传，可仅复制 `file/s3_list_upload_parts` 的**响应JSON正文**到本地临时文件；不要导出HAR、复制请求头或URL参数。此观察不是插件自动执行的动作，也不要求向任何人提交原始响应。

在配置好SDK和插件依赖的本地测试环境运行：

```sh
PYTHONPATH=/path/to/MovieClaw/src:/path/to/plugin-parent \
  python -m cloud_123_personal.acceptance < response.json > shape-report.json
```

工具完全离线，只输出已知字段的类型、列表长度和字段出现次数；不输出文件ID、MD5、会话ID、URL、token、任意未知键或值。输入上限1MiB。检查报告再分享；原始响应由用户自行处理，不进入代码仓库。

分别观察新会话、确认一片后、暂停重启后、全部片完成前、合并后、会话失效时的返回。`shape-report.json`只是结构线索，**不能证明分页完整性、已提交状态或跨域协议兼容，不能直接启用猜测解析**。需要语义证据与隔离复现后再更新适配器。
