# 演职人员中文刮削（`cast-cn`）

用豆瓣补齐 MovieClaw 条目详情页「演职员」一行：**中文名、中文角色、缺失的头像**。

只改条目目录里的 `movie.nfo` / `tvshow.nfo` 的 `<actor>` 节点，不碰视频、不碰数据库；
写前备份、原子写，写完触发一次元数据刷新并复核。主程序吸收 NFO 后，详情页、
人物页和 jellyfin 兼容层看到的都是同一份中文信息。

## 它怎么工作

1. **触发**：入库事件（新片到达）、定时全库补跑、手动运行（插件网页或命令行）。
2. **取数**：用条目的标题（剧集带季号，电影排除季条目）搜豆瓣，取候选条目的
   演职员表；搜索带负缓存，匹配逻辑升级后自动失效。
3. **匹配**：TMDB 姓名与豆瓣姓名做归一化匹配——折叠常见日中字形变体
   （聡/聪、瀬/濑、戸/户 等 18 组），精确匹配失败后做包含兜底（豆瓣常把假名
   转译成中文，如 上坂すみれ → 上坂堇）；歧义先交给角色收窄，仍不唯一就放弃。
4. **合并**：按设置补空缺或覆盖姓名/角色、按策略补头像，可删「仍无中文」
   和「无头像」的演员；`<tmdbid>` 默认保留（人物页可点）。
5. **写入与复核**：NFO 写前备份、原子写，然后触发一次元数据刷新；复核发现
   角色翻回英文会清掉待刷新标记并重试完整流程（重写必能打破指纹守卫）。

## 设置

| 字段 | 标题 | 默认 |
|---|---|---|
| `enabled` | 启用插件 | 开 |
| `libraries` | 媒体库 | 空 = 全部电影/剧集库 |
| `condition` | 处理条件 | 全部 |
| `avatar_policy` | 头像策略 | 保留现有头像 |
| `force_name` / `force_role` | 强制覆盖中文名 / 中文角色 | 关 |
| `remove_non_chinese` | 删除仍无中文的演员 | 关 |
| `remove_no_avatar` | 删除无头像的演员 | 关 |
| `keep_person_links` | 保留人物页链接 | 开 |
| `batch_size` | 每批并发显示（1–50） | 6 |
| `max_items_per_run` | 每轮最多处理（1–1000） | 100 |
| `delay_seconds` | 入库延迟（秒） | 0 |
| `dry_run` | 只预览不写入 | 关 |
| `public_base_url` | 外部访问地址 | 空 = 读应用设置 |
| `douban_api_base_url` | 豆瓣接口地址 | 默认官方移动接口 |

`libraries` 直接填媒体库名称（如：电影、国产剧、电视4），也兼容数字 id；
`condition` 取「全部 / 演员非中文 / 角色非中文」。

## 入口

- **插件网页**：装好后左侧栏「演职刮削」（`/apps/cast-cn`）——状态统计、
  预览整库（dry-run）、立即运行、最近处理记录、跳转设置与定时任务。
- **定时任务**：「设置 → 定时任务 → 演职人员中文刮削补跑」，默认每天 04:00。
- **命令行**：`mclaw plugins cast-cn run|report|restore`（运行 / 报告 / 恢复 NFO 备份）。

全库补跑走**批次窗口**：每批只排队 `batch_size` 条，整批处理完并从活动中心
消失后才排下一批；批内失败自动忽略，取消补跑会连带取消批内任务。

## 权限与契约

- 宿主操作：`app.show`、`library.list`、`library.items.list`、`library.items.get`、
  `library.items.refresh-metadata`、`jobs.wait`、`search.titles`
- 路径：媒体库目录读写（只写 `movie.nfo` / `tvshow.nfo` 与备份）
- 网络：仅访问豆瓣（接口地址可在设置里换成反代）
- 契约：`library.items.arrived`、`scheduled-tasks`、`job-handlers`

## 已知限制

- 豆瓣搜不到的条目（冷门片、接口波动）记为失败，下一轮定时补跑自动重试；
  每条的原因都写进插件报告与网页。
- 演员头像优先用 TMDB/本地已有的；豆瓣头像只用来补缺失（可改为豆瓣优先）。
- NFO 的 `<actor><tmdbid>` 默认保留，人物页仍指向 TMDB（姓名可能仍是英文）；
  不想出现不一致可关闭「保留人物页链接」。
