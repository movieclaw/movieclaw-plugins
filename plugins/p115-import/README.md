# 115 分享转存入库（`p115-import`）

把 115 分享链接、ed2k、磁力直接转存进媒体库：识别是哪部作品、进哪个库、按命名模板落位，
转存完只扫这部作品的网盘目录并逐文件核验。全程复用 MovieClaw 自己的识别、分库、命名与
季集仲裁，插件不自建一套匹配规则。

## 它做的事

1. **受理**：链接一进来就落成持久任务，同一批的活跃任务复用，不同批次不串单；网络中断在原检查点续跑，不会重新转存一遍。
2. **识别**：交给宿主的 `dl.resolve-target`（与手动下载弹窗同一条链）收敛唯一 TMDB 身份和媒体库。
   候选有冲突、多个同名、分享里的 TMDB 标记互相矛盾时一律停下等人确认，绝不自动挑一部。
3. **比体积**：同一季集只留最大一份。
4. **转存**：进库网盘目录下的隐藏暂存目录（`.p115-import`），按命名模板改名后移进正式目录；
   批量异名改名走 115 网页接口，移动优先走开放平台批量接口，没有授权就用网页批量接口。
5. **核验**：只扫描本次作品的网盘目录（`library.scan.start` 的 `cloud_paths`），不触发整库扫描；
   SHA1 + 体积 + 名字三重核对，作品/季集/路径/体积全部对上才算入库。

## 不替你做决定的部分

- **不自动删旧文件**。核验新文件更大后旧版先留着，只在看板上记「待清理」；清理要走独立入口，
  先逐项列出旧路径、体积、替代文件与宿主删除演练结果，确认具体清单后才入队（15 分钟确认票据、
  逐条编号核对、加密快照、去重）。站点 H&R 与做种要求由下载器那边管，插件只处理纯网盘旧文件。
- **不改名不确定的作品**。命名用全局有效语言与库级覆盖，中英文片名分别取公开元数据里对应的字段；
  拿不到该语言的命名译名时明确停住，不拿英文回落冒充其他语言。
- **不猜季集**。季集号沿用宿主的批次仲裁与台账守卫，不按单文件盲猜。

## 用法

侧栏「115 入库」：提交框（和企微转发同一套受理）、转存与核验进度、失败重试与候选确认、
空暂存目录清理、待清理旧文件预览与确认。也可以走命令：

```bash
mclaw plugins p115-import plan <链接>          # 只预演：识别、比体积、算落点
mclaw plugins p115-import apply <链接> --yes   # 真提交：识别 → 转存 → 扫描 → 核验
mclaw plugins p115-import status               # 登录与授权状态
mclaw plugins p115-import check                # 两条通道自检（只读）
mclaw plugins p115-import board                # 任务看板数据
mclaw plugins p115-import request <请求 id>     # 单次受理的进度
mclaw plugins p115-import cancel <任务 id>      # 取消，保留文件与检查点
mclaw plugins p115-import cleanup-old --dry-run # 只预览待清理旧文件
mclaw plugins p115-import wecom.ingest-url     # 取企微转发用的入库地址
```

## 登录与设置

- **网页登录（扫码）**：转存只能走 115 网页接口（开放平台没有分享转存）。选一个你其他工具
  （MovieClaw 自带网盘、CloudDrive2、OpenList）没在用的登录端，否则会互相踢下线。
- **开放平台授权（可选）**：填 AppID 并扫码授权后，建目录、单项改名、移动、删除优先走官方接口并获得批量移动。
- **结果通知（可选）**：填 `wecom-notify` 给出的签名推送地址，成功/失败由它发消息；留空只写日志。
- 原链接、提取码与检查点加密存储；日志与报错里不出现 Cookie 与令牌。

## 权限

宿主操作：`dl.resolve-target`、`discover.get-title-details`、`library.list`、`library.items.get`、
`library.scan.start`、`jobs.show`、`jobs.list`、`jobs.retry`、`jobs.cancel`、`scrape.show`，
以及**危险操作** `library.items.delete-file`（只在你确认了具体旧文件清单之后才会调用）。

只读读取宿主 NER 模型目录（默认 `/app/models/torrent-ner`），经文件接口读到插件私有临时目录里使用，
不改模型、不写媒体目录。运行方式 `process`（独立低权限进程），联网。

网页会以打开它的人的身份运行：管理员打开时拥有管理员的全部权限。侧栏只有「115 入库」一项，管理员可见。

## 已知限制

- 模型目录写成 `/app/models/torrent-ner`（容器镜像的默认路径）。用非 Docker 部署或把
  `MOVIECLAW_NER_DIR` 指到别处时，需要改这个常量再装。
- 命名只认中英文与原名三种字段：公开详情接口没提供日语、法语、繁体等命名译名，模板用 `{title}`
  且库语言是这些时插件会明确停止，不会拿别的语言凑。
- 批量 50 项是插件的保守分块，不是 115 服务端的上限；不做并发提速，沿用单账号限速。
