# 会话管家（session-keeper）

AI 会话上下文自动压缩：达到阈值就把历史折成交接摘要，让后续请求始终小而快，持续省 token。
当前版本 **0.1.0**。

## 它做什么

可靠订阅 `agent.run.finished`（每轮对话结束，回答完或出错都会广播），读一次轻量轨迹
（`session.get-transcript`，view=chat），统计**自上次压缩以来的用户消息数**与**最近一次回复记录的输入 token**。
满足任一条件就调 `session.compact-context` 压缩上下文：保留预算内的用户原话 + 生成交接摘要，
**只压不删**，完整轨迹保留，后续请求从压缩历史继续。

为什么盯输入 token：`prompt_tokens` 是每次请求的全量输入（历史 + 本轮），它降不下来上下文就一直贵，
所以它比「消息条数」更早、更准地反映「该压了」。

## 保护机制

- **冷却**：同一会话两次压缩至少间隔 `cooldown_minutes`（默认 10 分钟），避免连续压；
- **运行中会话跳过**：宿主会拒绝压缩正在跑的会话，插件记一条日志，下一轮结束再试；
- **幂等**：按事件 id 去重，同一事件投递两次不会压两次；
- **成本可控**：压缩本身是一次模型调用，只在「继续聊会贵得多」时才触发。

## 设置

| 项 | 默认 | 说明 |
|---|---|---|
| 消息数阈值 `max_messages` | 16 | 自上次压缩起累计的用户消息达到即压缩 |
| 输入 token 阈值 `max_prompt_tokens` | 60000 | 最近一次请求的输入 token 达到即压缩 |
| 冷却分钟 `cooldown_minutes` | 10 | 同一会话两次压缩的最小间隔 |
| 排除的会话 `exclude_sessions` | 空 | 这些会话不自动压缩（一行一个会话 ID） |

## 权限与数据

- 宿主操作：`session.get-transcript`（读会话轨迹统计长度）、`session.compact-context`（执行压缩）。都触及对话内容，安装时单独列出、需要批准；
- 事件：`agent.run.finished`；
- 不联网、不写文件；只在插件持久数据里记「各会话上次压缩时间」与近期事件 id（各 300 条上限）。

## 与「记忆与上下文管家（mc-memory）」的关系

`mc-memory` 已把本插件的能力并了进去，并共用同一次轨迹读取。只想压缩、不要记忆库时单装本插件最轻；
两个都装会各压一次，**不必同时启用**。
